# AGENTS.md

## Назначение

Этот файл описывает правила работы AI-агентов в проекте **Каталог NapitkiBerkat**.

Главное правило проекта:

```text
Сначала spec -> потом plan -> потом code
```

Если требования нет в документации, его нельзя делать в коде. Если требование неясно, его нужно уточнить. Если требование противоречит уже утвержденным specs, работу нужно остановить до уточнения.

## Язык работы

- Общение с владельцем проекта ведется на русском языке.
- Документация проекта пишется на русском языке.
- Технические названия файлов, папок, API, переменных и команд можно писать на английском.

## Структура документации

Основные документы проекта находятся в `docs/`.

Текущие слои документации:

- `docs/00-global-spec.md` - общее понимание проекта;
- `docs/features/` - подробные feature specs;
- `docs/technical/` - technical specs;
- `docs/user-stories/` - user stories.

Следующие слои могут быть добавлены позже:

- skills / visual rules;
- work plans;
- implementation notes.

## Правила изменения документации

- Не удалять принятые решения без явного подтверждения владельца.
- Не добавлять новую функциональность только потому, что она кажется полезной.
- Если появилась новая идея, сначала внести ее в подходящий spec.
- Если documents противоречат друг другу, сначала перечислить противоречия и дождаться подтверждения правок.
- Не смешивать разные слои документации без необходимости.
- Global spec должен оставаться общим и не дублировать все детали feature specs.
- Feature specs описывают поведение функций.
- Technical specs описывают техническую реализацию уже согласованного поведения.
- User stories проверяют реальные пути пользователей и не должны добавлять новую логику сами по себе.

## Правила разработки

Разработка кода запрещена, пока владелец явно не подтвердит переход к work plans и implementation.

До этого можно:

- читать документацию;
- создавать и править specs;
- искать противоречия и серые зоны;
- предлагать структуру документов;
- готовить черновики планов только после запроса владельца.

Нельзя:

- создавать приложение;
- писать компоненты;
- подключать Supabase;
- создавать базу данных;
- настраивать Vercel;
- писать production-код;
- устанавливать зависимости;
- делать миграции.

## Главные решения проекта

- Проект: **Каталог NapitkiBerkat**.
- Формат: каталог-сайт для оптового магазина напитков.
- Клиенты: кафе, рестораны, домашние клиенты и другие покупатели напитков.
- Основной сценарий клиента: открыть ссылку, выбрать напитки, собрать заказ, отправить в WhatsApp.
- Заказы в первой версии не сохраняются в базе.
- Основной канал заказа: WhatsApp.
- Админка нужна владельцу для управления товарами, ценами, фото, вкусами, категориями, статусами и сортировкой.
- Вход в админку: один общий логин и пароль.
- База данных: Supabase Postgres.
- Фото: Supabase Storage.
- Размещение сайта: Vercel.

## Правила первой версии

- Нет регистрации клиентов.
- Нет личного кабинета клиента.
- Нет онлайн-оплаты на сайте.
- Нет разных цен для разных клиентов.
- Нет точных складских остатков.
- Нет CRM.
- Нет автоматического расчета точной стоимости доставки.
- Нет автоматической проверки города в адресе.
- Нет сложной системы ролей админки.

## Работа с Git

- Не делать commit без явной просьбы владельца.
- Перед ответом о готовности к commit проверить `git status` и `git diff --check`.
- Не откатывать чужие изменения без явной просьбы владельца.
- Не использовать destructive-команды вроде `git reset --hard` без прямого указания владельца.

## Безопасность

- Не хранить в репозитории пароли, ключи Supabase, ключи Vercel и другие секреты.
- Не коммитить `.env` с реальными значениями.
- `SUPABASE_SERVICE_ROLE_KEY` нельзя отправлять в браузер и нельзя хранить в клиентском коде.
- Админские действия должны проходить через проверку входа.

## Перед началом любой работы

AI-агент должен:

1. Понять, к какому слою относится задача: spec, user stories, technical spec, work plan или code.
2. Проверить существующие документы.
3. Убедиться, что задача не противоречит утвержденным решениям.
4. Если задача неясна, сначала уточнить.
5. Если задача ясна и относится к документации, внести точечные правки.
