# План и роудмап разработки v0.1

## 1. Назначение документа

Этот документ описывает логический порядок первой разработки проекта **Каталог NapitkiBerkat**.

Он нужен, чтобы начинать разработку маленькими проверяемыми шагами, а не пытаться сразу сделать весь проект целиком.

Главное правило остается прежним:

```text
Сначала spec -> потом plan -> потом code
```

Код пишется только по утвержденным specs.

Этот документ не заменяет конкретные work plans.

Конкретные планы разработки для отдельных веток хранятся в `docs/work-plans/`.

Хронологическая история уже выполненных работ хранится в `docs/roadmap/`.

## 2. Текущая точка

На момент создания роудмапа уже есть:

- global spec;
- feature specs;
- design spec;
- technical specs;
- user stories;
- старый HTML-каталог как источник данных;
- черновик извлеченных данных из старого каталога.

Файлы старого каталога лежат здесь:

- `data/source-old-catalog/index.html`;
- `data/source-old-catalog/photos/`.

Файлы извлеченных данных лежат здесь:

- `data/import/old-catalog-products.draft.json`;
- `data/import/old-catalog-products.draft.csv`;
- `data/import/old-catalog-import-report.md`.

Из старого каталога уже извлечено:

- 7 категорий;
- 86 товаров;
- 31 товар с выбором вкусов;
- 108 вариантов вкусов;
- 4 товара без найденного основного фото.

Эти данные пока не загружены в Supabase.

## 3. Главный порядок разработки

Разработка первой версии идет в таком порядке:

1. Подготовить приложение.
2. Подключить Supabase.
3. Создать структуру базы данных.
4. Подготовить импорт старого каталога.
5. Загрузить реальные товары и фото.
6. Сделать клиентский каталог.
7. Сделать корзину.
8. Сделать оформление заказа и WhatsApp.
9. Сделать админку входа.
10. Сделать админку управления каталогом.
11. Проверить нестандартные состояния.
12. Подготовить деплой на Vercel.

## 4. Этап 1. Подготовка приложения

Цель этапа: создать техническую основу проекта.

Что делаем:

- создаем Next.js / React / TypeScript приложение;
- настраиваем базовую структуру папок;
- добавляем базовую главную страницу;
- добавляем страницу админки без реальной логики;
- готовим файл примера переменных окружения;
- проверяем, что проект запускается локально.

Что не делаем на этом этапе:

- не делаем дизайн каталога полностью;
- не подключаем реальные товары;
- не пишем всю админку;
- не загружаем фото.

Проверка этапа:

- приложение запускается локально;
- открывается клиентская главная страница;
- открывается заготовка страницы входа в админку;
- в проекте нет реальных секретных ключей.

## 5. Этап 2. Supabase и база данных

Цель этапа: подготовить место, где будут храниться товары, категории, вкусы и фото.

Что делаем:

- создаем проект Supabase;
- подключаем приложение к Supabase;
- создаем таблицы по technical specs;
- создаем правила для хранения фото в Supabase Storage;
- проверяем, что приложение может читать данные из Supabase.

Главные сущности:

- категории;
- товары;
- вкусы;
- фото;
- статусы товара;
- порядок показа в **Все напитки**;
- порядок показа внутри категории.

Проверка этапа:

- таблицы есть в Supabase;
- приложение может получить тестовые данные;
- секретные ключи не попадают в браузер;
- фото хранятся в Supabase Storage.

## 6. Этап 3. Подготовка импорта каталога

Цель этапа: превратить старый каталог в данные, которые можно загрузить в Supabase.

Что делаем:

- проверяем `old-catalog-products.draft.json`;
- сверяем 4 товара без основного фото;
- решаем, что делать с лишними или отсутствующими фото;
- готовим скрипт импорта категорий, товаров и вкусов;
- готовим загрузку фото в Supabase Storage.

Важно:

- если у вкуса нет отдельного фото, используется основное фото товара;
- товар без основного фото, цены или количества штук в одной уп не показывается клиенту;
- такие товары могут быть сохранены как черновики.

Проверка этапа:

- понятно, какие товары готовы к публикации;
- понятно, какие товары останутся черновиками;
- импорт можно запустить повторно без хаоса в данных.

## 7. Этап 4. Импорт реальных данных

Цель этапа: загрузить текущий ассортимент в Supabase.

Что делаем:

- загружаем категории;
- загружаем товары;
- загружаем вкусы;
- загружаем фото;
- связываем товары и вкусы с фото;
- задаем начальный порядок товаров.

Проверка этапа:

- в Supabase есть 7 категорий;
- в Supabase есть 86 товаров;
- товары имеют цены;
- товары имеют количество штук в одной уп;
- товары имеют категории, если они опубликованы;
- фото открываются из Supabase Storage;
- товары без обязательных данных не попадают в клиентский каталог.

## 8. Этап 5. Клиентский каталог

Цель этапа: клиент может открыть сайт и увидеть ассортимент.

Что делаем:

- показываем фильтр **Все напитки** первым;
- показываем категории после **Все напитки**;
- показываем карточки товаров;
- показываем фото, название, цену и количество штук в одной уп;
- добавляем поиск по названию;
- добавляем выбор вкусов у товаров, где вкусы есть;
- показываем товары **нет в наличии**, но не даем добавить их в заказ;
- скрываем черновики, скрытые и удаленные товары.

Проверка этапа:

- клиент видит весь каталог;
- поиск работает в выбранном фильтре;
- фильтр **Все напитки** показывает все видимые товары;
- фильтр категории показывает товары этой категории;
- товар с вкусами остается одной карточкой;
- при выборе вкуса может меняться фото;
- если у вкуса нет фото, показывается основное фото товара.

## 9. Этап 6. Корзина

Цель этапа: клиент может собрать заказ без ручного написания списка в WhatsApp.

Что делаем:

- добавляем товар в заказ;
- увеличиваем и уменьшаем количество через плюс и минус;
- показываем количество в формате `уп`;
- считаем сумму только по доступным позициям;
- показываем подсказку до бесплатной доставки от 8000 рублей;
- даем удалить одну позицию;
- даем очистить корзину;
- храним корзину между обновлениями страницы.

Проверка этапа:

- повторное добавление того же товара увеличивает количество;
- разные вкусы одного товара становятся разными позициями;
- минус на `1 уп` удаляет позицию;
- недоступная позиция остается видимой, но не участвует в сумме;
- заказ нельзя отправить, если в корзине нет доступных позиций.

## 10. Этап 7. Оформление заказа и WhatsApp

Цель этапа: клиент отправляет понятный заказ работнику магазина.

Что делаем:

- добавляем страницу или блок оформления заказа;
- делаем адрес обязательным;
- добавляем пример адреса: `Грозный ул Назабраева 92`;
- добавляем выбор оплаты: наличные или перевод;
- показываем итоговую сумму доступных позиций;
- показываем строку доставки;
- формируем WhatsApp-сообщение;
- открываем WhatsApp по номеру магазина.

Формат начала сообщения:

```text
Добрый день! Хочу сделать заказ!
```

Пример строки товара:

```text
Мохито клубника - 1уп
```

Проверка этапа:

- в WhatsApp попадают только доступные позиции;
- сумма считается только по доступным позициям;
- адрес попадает в сообщение;
- способ оплаты попадает в сообщение;
- доставка попадает в сообщение;
- источник заказа в сообщение не добавляется.

## 11. Этап 8. Админка: вход

Цель этапа: закрыть управление каталогом от клиентов.

Что делаем:

- создаем страницу входа в админку;
- используем один общий логин и пароль;
- создаем серверную сессию через cookie;
- добавляем выход из админки;
- закрываем админские страницы от неавторизованного доступа.

Проверка этапа:

- без входа админка не открывается;
- с правильным логином и паролем админка открывается;
- после выхода админка снова закрыта;
- в клиентском каталоге нет видимой ссылки на админку.

## 12. Этап 9. Админка: управление каталогом

Цель этапа: владелец может менять каталог без разработки.

Что делаем:

- список товаров в админке;
- поиск товара по названию;
- добавление товара;
- редактирование товара;
- удаление товара;
- скрытие товара;
- управление статусом **нет в наличии**;
- управление ценой;
- управление количеством штук в одной уп;
- управление основным фото;
- управление вкусами;
- управление фото вкусов;
- управление категориями;
- ручная сортировка товаров в **Все напитки**;
- ручная сортировка товаров внутри категории;
- отдельные списки для скрытых товаров и черновиков.

Разбивка этапа на отдельные work plans:

1. **Базовое добавление и редактирование товара**:
   - добавить товар как черновик;
   - открыть существующий товар на редактирование;
   - изменить название, категорию, цену, количество штук в одной уп и статус товара;
   - не менять фото, вкусы, категории и drag-and-drop сортировку в этом work plan.
2. **Фото товара**:
   - загрузить новое основное фото;
   - заменить основное фото товара;
   - сохранить правила обязательного фото для публикации товара.
3. **Быстрые действия и удаление товара**:
   - удалить товар с подтверждением;
   - скрыть товар отдельной быстрой кнопкой с карточки;
   - вернуть скрытый товар отдельной быстрой кнопкой с карточки.
4. **Вкусы товара**:
   - управлять списком вкусов товара;
   - менять `has_flavor_choice`;
   - загружать и заменять фото вкуса;
   - задавать отдельные цены вкусов;
   - отмечать отдельный вкус как **нет в наличии**.
5. **Категории**:
   - добавить категорию;
   - переименовать категорию;
   - удалить категорию по правилам specs.
6. **Сортировка**:
   - менять порядок категорий;
   - менять порядок товаров в **Все напитки** через drag-and-drop;
   - менять порядок товаров внутри категории через drag-and-drop.

Проверка этапа:

- админ может добавить товар;
- админ может поменять цену;
- админ может отметить товар или вкус как **нет в наличии**;
- админ может скрыть товар;
- админ может удалить товар;
- админ может поменять порядок товаров перетаскиванием;
- клиентский каталог сразу показывает актуальные данные.

## 13. Этап 10. Нестандартные состояния

Цель этапа: сайт не должен ломаться в обычных проблемных ситуациях.

Что проверяем:

- пустой каталог;
- пустая категория;
- поиск без результата;
- товар без обязательных данных;
- товар стал недоступен после добавления в корзину;
- цена изменилась после добавления в корзину;
- корзина пустая;
- в корзине остались только недоступные позиции;
- WhatsApp не открылся;
- админ ввел неверный логин или пароль;
- фото не загрузилось.

Проверка этапа:

- пользователь видит понятное сообщение;
- пользователь не попадает в тупик;
- недоступные позиции не уходят в WhatsApp;
- клиенту не показываются черновики, скрытые и удаленные товары.

## 14. Этап 11. Подготовка к деплою

Цель этапа: подготовить проект к реальной ссылке для клиентов.

Что делаем:

- настраиваем Vercel;
- добавляем переменные окружения;
- подключаем Supabase к продакшену;
- проверяем сборку проекта;
- проверяем сайт на телефоне;
- проверяем работу WhatsApp-ссылки;
- подключаем домен, когда владелец будет готов.

Проверка этапа:

- сайт открывается по ссылке Vercel;
- клиентский каталог работает;
- заказ отправляется в WhatsApp;
- админка открывается только после входа;
- секреты не лежат в репозитории.

## 15. Первый минимальный рабочий результат

Первый результат, который стоит получить как можно раньше:

```text
Реальные товары из Supabase показываются в клиентском каталоге.
```

В этот момент еще может не быть полной корзины и админки, но мы уже проверим самое главное:

- база работает;
- импорт работает;
- фото работают;
- карточки товаров строятся на реальных данных;
- структура данных подходит проекту.

После этого разработка станет намного понятнее, потому что мы будем видеть настоящий каталог, а не тестовые примеры.

## 16. Что не входит в первый старт разработки

На старте не делаем:

- регистрацию клиентов;
- личный кабинет;
- онлайн-оплату;
- разные цены для разных клиентов;
- точные складские остатки;
- CRM;
- автоматический расчет точной доставки;
- автоматическую проверку города по адресу;
- сложные роли в админке.

Эти вещи можно обсуждать позже, когда первая версия начнет решать главную задачу.

## 17. Критерий готовности первой версии

Первая версия считается готовой, когда:

- клиент открывает ссылку и видит актуальный ассортимент;
- клиент может найти товар по названию;
- клиент может фильтровать товары по категориям;
- клиент может выбрать вкус, если он есть;
- клиент может собрать заказ в уп;
- клиент видит мотивацию до бесплатной доставки от 8000 рублей;
- клиент может указать адрес и оплату;
- клиент может отправить заказ в WhatsApp;
- работник получает понятное WhatsApp-сообщение;
- владелец может войти в админку;
- владелец может менять товары, цены, фото, вкусы, категории, статусы и порядок;
- сайт развернут на Vercel;
- данные и фото хранятся в Supabase.
