# Global Spec v0.2

## 1. Назначение документа

Этот документ является единым главным spec проекта **Каталог NapitkiBerkat**.

Он объединяет общее понимание проекта и функциональную карту, чтобы не поддерживать две похожие версии одного и того же описания.

Документ фиксирует:

- для кого создается проект;
- какую проблему решает проект;
- какие роли есть в проекте;
- что должен уметь клиент;
- что должен уметь владелец через админку;
- как формируется заказ;
- какие правила действуют для товаров, доставки и WhatsApp-сообщения;
- что входит и не входит в первую версию.

Этот документ не описывает техническую реализацию, дизайн, базу данных, API, фреймворки или конкретную верстку. Это будет описываться позже в feature specs, technical specs и skills.

## 2. Название проекта

Название проекта: **Каталог NapitkiBerkat**.

## 3. Суть проекта

Проект представляет собой каталог-сайт для оптового магазина напитков NapitkiBerkat.

Клиент получает ссылку на сайт, открывает ассортимент, смотрит цены, выбирает нужные товары и отправляет заказ в WhatsApp.

Главная идея: заменить ручную отправку ассортимента, цен и уточнений одним удобным каталогом, который помогает клиенту быстро понять ассортимент, цену, доступность товара, доставку и способ оформления заказа.

## 4. Для кого проект

Основные клиенты:

- кафе;
- рестораны;
- клиенты, которые заказывают напитки на дом;
- другие покупатели напитков.

Домашние клиенты идут по тому же сценарию, что кафе, рестораны и другие клиенты: открывают каталог, выбирают товары и отправляют заказ в WhatsApp.

Проект ориентирован не на случайный розничный просмотр, а на клиентов, которые уже заинтересовались покупкой и хотят быстро увидеть доступный ассортимент.

## 5. Основная проблема

Сейчас клиент часто спрашивает ассортимент и цены отдельно.

Показывать весь ассортимент вручную сложно, долго и неудобно:

- нужно каждый раз объяснять, какие товары доступны, а каких сейчас нет;
- нужно отправлять цены;
- нужно отвечать на повторяющиеся вопросы;
- клиенту сложно сравнивать товары;
- заказ может теряться в переписке;
- менеджер тратит много времени на однотипную коммуникацию.

## 6. Цели проекта

Клиентская цель:

- быстро увидеть ассортимент напитков;
- понять цены;
- найти товар по названию;
- выбрать нужные товары;
- сформировать заказ;
- увидеть сумму товаров и информацию по доставке;
- отправить заказ в WhatsApp.

Бизнес-цель:

- быстрее закрывать интерес клиента;
- уменьшить ручной труд при показе ассортимента;
- упростить процесс заказа;
- упростить понимание доставки;
- повысить вероятность, что клиент дойдет до заказа;
- дать владельцу удобный способ менять товары, цены и отметку "нет в наличии" без разработки.

## 7. Роли проекта

### 7.1. Клиент

Клиент открывает каталог по ссылке, смотрит ассортимент, выбирает товары, указывает данные заказа и отправляет заказ в WhatsApp.

### 7.2. Владелец каталога

Владелец управляет каталогом через админку.

Он должен иметь возможность без разработки менять товары, цены, фото, категорию товара и отметку "нет в наличии".

### 7.3. Работник магазина

Работник получает заказ в WhatsApp и должен быстро понять:

- какие товары заказали;
- сколько упаковок нужно;
- какая сумма товаров;
- какая информация по доставке;
- куда доставлять;
- как клиент хочет оплатить заказ.

## 8. Основной сценарий клиента

1. Клиент пишет или звонит и интересуется ассортиментом.
2. Ему отправляют ссылку на каталог.
3. Клиент открывает каталог на телефоне или компьютере.
4. Клиент видит категории напитков.
5. Клиент выбирает категорию или ищет товар по названию.
6. Клиент смотрит товары, фото и цены.
7. Клиент выбирает нужные товары.
8. Клиент задает количество упаковок через плюс и минус.
9. Клиент проверяет состав заказа.
10. Клиент указывает адрес доставки.
11. Клиент видит сумму товаров и информацию по доставке.
12. Клиент выбирает способ оплаты: наличные или перевод.
13. Клиент нажимает "Отправить в WhatsApp".
14. В WhatsApp формируется понятное сообщение с заказом.
15. Работник магазина получает заказ и обрабатывает его в чате.

Основной канал передачи ссылки: WhatsApp или другая переписка с клиентом.

Приоритет устройства: **мобильный телефон**.

Сайт также должен нормально работать на компьютере.

## 9. Возможности клиента

Клиент должен иметь возможность:

- открыть каталог по ссылке;
- увидеть категории напитков;
- найти товар по названию;
- посмотреть товары внутри категорий;
- увидеть фото товара;
- увидеть название товара;
- увидеть цену товара;
- увидеть объем товара;
- увидеть сколько штук в одной упаковке;
- понять, есть ли товар для заказа;
- выбрать количество упаковок;
- изменить количество упаковок;
- убрать товар из заказа;
- увидеть выбранные товары;
- увидеть сумму товаров;
- указать адрес доставки;
- увидеть информацию по доставке;
- выбрать способ оплаты;
- отправить заказ в WhatsApp.

## 10. Возможности владельца

Владелец должен иметь возможность:

- войти в админку по логину и паролю;
- видеть список товаров в админке;
- найти товар по названию в админке;
- добавить новый товар;
- отредактировать существующий товар;
- изменить название товара;
- изменить категорию товара;
- изменить цену товара;
- изменить фото товара;
- изменить описание товара;
- изменить объем товара;
- изменить информацию об упаковке;
- отметить товар как "нет в наличии";
- снять отметку "нет в наличии";
- скрыть товар из клиентского каталога;
- вернуть скрытый товар в клиентский каталог.

Перед скрытием товара из каталога нужно подтверждение.

Админка должна быть простой: вход по логину и паролю без сложной системы ролей.

Админка не предназначена для клиентов.

## 11. Данные товара

В админке должны редактироваться:

- название;
- категория;
- цена;
- фото;
- описание;
- объем;
- упаковка;
- отметка "нет в наличии".

Фото товаров обязательны для клиентского каталога.

Точное наличие или остатки в штуках указывать не нужно.

Единица заказа: **упаковка**.

Клиент не должен вручную вводить количество товара текстом. Количество упаковок выбирается через плюс и минус, как в маркетплейсах.

## 12. Состояния товара

У товара есть три состояния.

### 12.1. Доступен для заказа

Товар виден клиенту и может быть добавлен в заказ.

### 12.2. Нет в наличии

Товар виден клиенту, остается на своем обычном месте в категории, но не может быть добавлен в заказ.

Это состояние нужно, чтобы клиент понимал, что товар обычно есть в ассортименте, но сейчас временно недоступен.

### 12.3. Скрыт из каталога

Товар не виден клиенту.

Владелец видит этот товар в админке и может вернуть его в каталог позже.

## 13. Категории каталога

В первой версии каталога нужны фиксированные категории:

- вода;
- газировки;
- лимонады;
- чай;
- натуральные напитки;
- энергетики;
- разные товары.

Владелец может выбирать категорию товара из фиксированного списка, но не управляет списком категорий через админку.

## 14. Заказ клиента

Заказ должен включать:

- выбранные товары;
- количество упаковок по каждому товару;
- цену каждого товара;
- сумму по каждой позиции;
- сумму товаров;
- адрес доставки;
- информацию по доставке;
- способ оплаты;
- текст, по которому работник понимает, что заказ пришел из каталога NapitkiBerkat.

Адрес доставки обязателен для отправки заказа.

Имя клиента указывать не нужно.

Сумма товаров должна быть видна всегда, как в корзине маркетплейса.

Способы оплаты в первой версии:

- наличные;
- перевод.

Онлайн-оплата на сайте не входит в первую версию.

## 15. Доставка

Информация по доставке входит в первую версию.

Правило доставки:

- если сумма товаров от 8000 рублей, доставка бесплатная;
- если сумма товаров меньше 8000 рублей, стоимость доставки сообщается в WhatsApp по тарифу.

Если сумма товаров меньше 8000 рублей, сайт не должен обещать точную итоговую сумму с доставкой. В заказе должна быть сумма товаров и понятная пометка, что стоимость доставки будет сообщена в WhatsApp.

## 16. WhatsApp-сообщение

После нажатия "Отправить в WhatsApp" должно формироваться аккуратное и понятное сообщение с заказом для работника магазина.

Минимальное содержание сообщения:

- заголовок заказа;
- список товаров;
- количество упаковок;
- цена по каждой позиции;
- сумма по каждой позиции;
- сумма товаров;
- информация по доставке;
- адрес доставки;
- способ оплаты.

## 17. Что не входит в первую версию

В первую версию не входят:

- регистрация клиентов;
- личный кабинет клиента;
- разные цены для разных клиентов;
- минимальный заказ;
- акции и скидки;
- избранные товары;
- онлайн-оплата на сайте;
- автоматическая синхронизация со складом;
- точные остатки товара в штуках;
- управление списком категорий через админку;
- сложная CRM;
- сложная система ролей и прав доступа;
- полноценный интернет-магазин с оплатой на сайте.

Эти возможности можно рассмотреть позже, если они понадобятся.

## 18. Нестандартные ситуации

Нужно предусмотреть следующие ситуации:

- клиент открыл каталог, но товаров пока нет;
- клиент открыл категорию, но в ней нет товаров;
- клиент ищет товар по названию, но ничего не найдено;
- товар есть в каталоге, но отмечен как "нет в наличии";
- клиент пытается отправить пустой заказ;
- клиент не указал адрес доставки;
- сумма товаров меньше 8000 рублей, поэтому стоимость доставки нужно сообщить в WhatsApp по тарифу;
- клиент не выбрал способ оплаты;
- владелец добавляет товар без фото;
- владелец добавляет товар без цены;
- владелец хочет временно убрать товар из каталога;
- клиент открывает каталог с телефона;
- клиент открывает каталог с компьютера.

## 19. Критерии успеха первой версии

Первая версия считается успешной, если:

- клиент может открыть ссылку на телефоне;
- клиент видит категории напитков;
- клиент видит товары, фото и цены;
- клиент может найти товар по названию;
- клиент может выбрать несколько товаров;
- клиент может менять количество упаковок через плюс и минус;
- клиент видит сумму товаров;
- клиент видит информацию по доставке;
- клиент может указать адрес доставки;
- клиент может выбрать способ оплаты;
- клиент может отправить заказ в WhatsApp;
- WhatsApp-сообщение понятно работнику магазина;
- владельцу не нужно вручную перечислять весь ассортимент каждому клиенту;
- владелец может через админку менять товары, цены, фото, описание, упаковку и отметку "нет в наличии".
