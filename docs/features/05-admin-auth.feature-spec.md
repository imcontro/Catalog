# Feature Spec: Admin Auth v0.1

## 1. Назначение

Этот spec описывает вход в админку.

Админка нужна владельцу, чтобы управлять каталогом без разработки.

## 2. Пользователь

Основной пользователь: владелец каталога.

Клиенты не должны иметь доступ к админке.

## 3. Что должно быть в первой версии

В первой версии нужен простой вход:

- логин;
- пароль;
- вход в админку;
- ошибка при неверном логине или пароле;
- выход из админки.

Сложная система ролей и прав доступа не нужна.

## 4. Основной сценарий входа

1. Владелец открывает страницу входа в админку.
2. Владелец вводит логин.
3. Владелец вводит пароль.
4. Владелец нажимает вход.
5. Если данные верные, открывается админка.
6. Если данные неверные, показывается ошибка.

## 5. Ошибка входа

Если логин или пароль неверные, владелец должен увидеть понятную ошибку.

Ошибка не должна раскрывать, что именно неверно: логин или пароль.

## 6. Выход из админки

Владелец должен иметь возможность выйти из админки.

После выхода админка не должна открываться без повторного входа.

## 7. Ограничения первой версии

В первую версию не входят:

- регистрация новых администраторов;
- восстановление пароля через email;
- роли и права доступа;
- отдельные аккаунты для разных работников;
- двухфакторная авторизация.

## 8. Нестандартные ситуации

Нужно предусмотреть:

- неверный логин или пароль;
- пустой логин;
- пустой пароль;
- владелец открыл админку без входа;
- владелец вышел из админки и пытается вернуться назад.

## 9. Правила первой версии

- Админка доступна по логину и паролю.
- Админка не предназначена для клиентов.
- Сложной системы ролей нет.
- Вход должен быть достаточно простым для владельца.

## 10. Вопросы для проверки владельцем

1. Нужен ли один общий логин или отдельный логин для магазина?
2. Нужно ли автоматически выходить из админки после долгого бездействия?
3. Нужно ли скрывать ссылку на админку от клиентов?
