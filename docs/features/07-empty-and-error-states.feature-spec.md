# Feature Spec: Empty And Error States v0.1

## 1. Назначение

Этот spec описывает общий подход к пустым, ошибочным и нестандартным состояниям проекта.

Конкретные состояния каждой части проекта описываются в соответствующих feature specs. Этот документ задает стиль сообщений и общий принцип поведения.

## 2. Зачем это нужно

Проект должен быть понятным не только в идеальном сценарии.

Если действие невозможно, пользователь должен увидеть понятное объяснение и следующий шаг.

## 3. Принцип сообщений

Сообщения должны быть:

- короткими;
- понятными;
- официальными;
- нетехническими.

Сообщение должно объяснять:

- что произошло;
- что нужно сделать дальше.

Сообщения не должны обвинять пользователя и не должны оставлять его в тупике.

## 4. Примеры смыслов сообщений

Для пустого каталога:

- товаров пока нет;
- владелец может добавить товары через админку;
- контакты магазина показывать не нужно.

Для пустой категории:

- в этой категории пока нет товаров;
- можно вернуться к другим категориям.

Для пустого поиска:

- по этому названию ничего не найдено;
- можно изменить запрос или выбрать категорию.

Для пустой корзины:

- товары пока не выбраны;
- нужно добавить товары из каталога.

Для отсутствующего адреса:

- адрес доставки обязателен;
- нужно указать адрес перед отправкой заказа.

Для отсутствующего способа оплаты:

- способ оплаты обязателен;
- нужно выбрать наличные или перевод.

Для товара без основного фото, цены или количества штук в одной уп в админке:

- товар можно сохранить как черновик;
- черновик не будет виден клиентам, пока не будут заполнены обязательные данные.

Для ситуации, когда WhatsApp не открылся:

- нужно показать официальное сообщение об ошибке;

Тексты доставки берутся из spec `04-delivery`.

## 5. Правила первой версии

- Пользователь не должен попадать в тупик.
- Если действие невозможно, нужно объяснить почему.
- Если нужно исправить данные, нужно показать, какие именно.
- Ошибки должны помогать завершить сценарий, а не просто запрещать действие.
- Сообщения должны быть в официальном стиле.
- Для пустого каталога контакты магазина показывать не нужно.
