# Feature Spec: Empty And Error States v0.1

## 1. Назначение

Этот spec описывает пустые, ошибочные и нестандартные состояния проекта.

Такие состояния нужны, чтобы клиент и владелец понимали, что происходит, даже если обычный сценарий прервался.

## 2. Зачем это нужно

Проект должен быть понятным не только в идеальном сценарии.

Если товаров нет, поиск ничего не нашел, адрес не указан или заказ пустой, пользователь должен видеть понятное объяснение и следующий шаг.

## 3. Состояния клиентского каталога

Нужно предусмотреть:

- каталог пустой;
- категория пустая;
- поиск ничего не нашел;
- товар отмечен как "нет в наличии";
- товар скрыт и не должен показываться клиенту.

## 4. Состояния корзины

Нужно предусмотреть:

- корзина пустая;
- клиент пытается отправить пустой заказ;
- товар в корзине стал "нет в наличии";
- товар в корзине был скрыт;
- изменилась цена товара.

## 5. Состояния оформления заказа

Нужно предусмотреть:

- адрес доставки не указан;
- способ оплаты не выбран;
- WhatsApp не открылся;
- сообщение для WhatsApp слишком длинное;
- сумма товаров меньше 8000 рублей и доставка будет уточняться в WhatsApp.

## 6. Состояния админки

Нужно предусмотреть:

- неверный логин или пароль;
- владелец пытается открыть админку без входа;
- владелец добавляет товар без названия;
- владелец добавляет товар без фото;
- владелец добавляет товар без цены;
- владелец не выбрал категорию;
- поиск в админке ничего не нашел;
- владелец хочет скрыть товар из каталога.

## 7. Принцип сообщений

Сообщения должны быть короткими и понятными.

Сообщение должно объяснять:

- что произошло;
- что нужно сделать дальше.

Сообщения не должны быть техническими.

## 8. Примеры смыслов сообщений

Для пустого каталога:

- товаров пока нет;
- владелец может добавить товары через админку.

Для пустой категории:

- в этой категории пока нет товаров;
- можно вернуться к другим категориям.

Для пустого поиска:

- по этому названию ничего не найдено;
- можно изменить запрос или выбрать категорию.

Для пустой корзины:

- товары пока не выбраны;
- нужно добавить товары из каталога.

Для отсутствующего адреса:

- адрес доставки обязателен;
- нужно указать адрес перед отправкой заказа.

## 9. Основные правила

- Пользователь не должен попадать в тупик.
- Если действие невозможно, нужно объяснить почему.
- Если нужно исправить данные, нужно показать, какие именно.
- Ошибки должны помогать завершить сценарий, а не просто запрещать действие.

## 10. Вопросы для проверки владельцем

1. Нужно ли писать сообщения в более официальном или более простом стиле?
2. Нужно ли для пустого каталога показывать контакты магазина?
3. Нужно ли клиенту показывать подсказку, если доставка меньше 8000 рублей будет по тарифу?
