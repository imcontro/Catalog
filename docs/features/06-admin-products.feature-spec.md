# Feature Spec: Admin Products v0.1

## 1. Назначение

Этот spec описывает управление товарами в админке.

Админка товаров нужна, чтобы владелец мог без разработки добавлять товары, менять цены, фото, вкусы, количество штук в одной уп, категорию, сортировку и состояние товара.

## 2. Пользователь

Основной пользователь: владелец каталога.

Клиенты не имеют доступа к админке.

## 3. Что владелец должен уметь

Владелец должен иметь возможность:

- видеть список товаров;
- найти товар по названию;
- добавить новый товар;
- отредактировать товар;
- удалить товар;
- изменить фото;
- изменить вкусы товара;
- изменить цену;
- изменить количество штук в одной уп;
- изменить категорию товара;
- добавить категорию;
- переименовать категорию;
- удалить категорию;
- менять порядок категорий через перетаскивание;
- менять порядок товаров в разделе "Все напитки" через перетаскивание;
- менять порядок товаров внутри категории через перетаскивание;
- отметить товар как "нет в наличии";
- снять отметку "нет в наличии";
- сохранить товар как черновик, если не хватает основного фото или цены;
- скрыть товар из клиентского каталога;
- вернуть скрытый товар в клиентский каталог;
- видеть скрытые товары в отдельном списке;
- видеть черновики в отдельном списке.

## 4. Поля товара

В товаре должны быть поля:

- название;
- категория;
- цена;
- фото;
- вкусы;
- количество штук в одной уп;
- статус товара.

Поле "количество штук в одной уп" показывает клиенту, сколько единиц товара находится в одной упаковке.

Примеры: **24 шт в уп**, **12 шт в уп**, **6 шт в уп**.

Количество штук в одной уп обязательно для клиентского каталога.

Если владелец сохраняет товар без количества штук в одной уп, товар можно сохранить как черновик.

Товар без количества штук в одной уп не должен показываться в клиентском каталоге.

Объем, тара или формат товара не хранятся отдельным полем. Если они важны для клиента, владелец указывает их в названии товара.

Пример названия: **Кока-Кола ж/б 0.33л**.

## 5. Категории

В первой версии владелец должен управлять списком категорий через админку.

При первом запуске можно использовать стартовый список категорий:

- вода;
- газировки;
- лимонады;
- чай;
- натуральные напитки;
- энергетики;
- разные напитки.

Владелец должен иметь возможность:

- добавить новую категорию;
- переименовать категорию;
- удалить категорию;
- изменить порядок категорий через перетаскивание.

Название категории должно быть уникальным.

Нельзя создать две категории с одинаковым названием.

Новая категория по умолчанию попадает в конец списка категорий.

Владелец выбирает категорию товара из актуального списка категорий.

Опубликованный товар должен иметь одну категорию.

Черновик можно сохранить без категории.

Категория с товарами не удаляется. Чтобы удалить категорию, владелец должен сначала перенести товары в другую категорию или удалить эти товары.

Если категория переименована, товары внутри нее остаются в этой категории.

Порядок категорий, заданный владельцем, используется в клиентском каталоге.

**Все напитки** не является категорией товара. Это системный клиентский фильтр, который автоматически показывает все видимые товары каталога.

Фильтр **Все напитки** всегда показывается первым перед категориями.

**Все напитки** нельзя удалить, переименовать или переместить в списке категорий.

## 6. Фото товара

Фото товара обязательно для клиентского каталога.

Владелец должен иметь возможность добавить или заменить фото товара.

Если владелец сохраняет товар без основного фото, товар можно сохранить как черновик.

Товар без основного фото не должен показываться в клиентском каталоге.

Если у товара несколько вкусов, у каждого вкуса может быть свое фото.

Фото вкуса не обязательно. Если у вкуса нет отдельного фото, в клиентском каталоге используется основное фото товара.

## 7. Цена товара

Цена товара обязательна для клиентского каталога.

Цены едины для всех клиентов, но разные вкусы одного товара могут иметь разные цены.

Разные прайсы для разных клиентов не входят в первую версию.

У вкусов одного товара в большинстве случаев одна цена.

Если отдельный вкус дороже или дешевле, владелец должен иметь возможность задать отдельную цену для этого вкуса.

Если владелец сохраняет товар без цены, товар можно сохранить как черновик.

Товар без цены не должен показываться в клиентском каталоге.

## 7.1. Вкусы товара

Товар может быть без выбора вкуса или иметь несколько вкусов.

Товар с несколькими вкусами остается одним товаром в админке и одной карточкой в клиентском каталоге.

Для каждого вкуса владелец должен иметь возможность указать:

- название вкуса;
- фото вкуса, если нужно;
- цену вкуса, если она отличается от общей цены товара;
- отметку "нет в наличии" для конкретного вкуса.

Если все вкусы товара отмечены как "нет в наличии", это не отдельный статус товара, а вычисляемое состояние. Товар остается видимым в каталоге, но недоступен для заказа, потому что все его вкусы недоступны.

## 8. Черновики, наличие и скрытие

У товара есть четыре разных статуса:

- доступен для заказа;
- черновик;
- "нет в наличии";
- скрыт из клиентского каталога.

Эти статусы не объединяются между собой: у товара должен быть один основной статус.

Черновик нужен для товара, который владелец начал добавлять, но еще не заполнил полностью.

Товар можно сохранить как черновик, если нет основного фото, цены или количества штук в одной уп.

Черновик виден только в админке и не показывается клиенту в каталоге.

Черновик нельзя добавить в заказ.

Чтобы товар появился в клиентском каталоге, нужно заполнить обязательные данные и убрать статус черновика.

В админке нужно различать следующие действия:

- сохранить товар как черновик;
- отметить товар как "нет в наличии";
- отметить отдельный вкус как "нет в наличии";
- скрыть товар из клиентского каталога.

Если товар отмечен как "нет в наличии", клиент видит товар, но не может добавить его в заказ.

Если отдельный вкус отмечен как "нет в наличии", клиент видит этот вкус, но не может выбрать его для заказа.

Если товар скрыт, клиент не видит товар вообще.

Перед скрытием товара нужно подтверждение.

Владелец должен иметь возможность удалить товар из админки.

Перед удалением товара нужно подтверждение.

Удаленный товар исчезает из клиентского каталога и из списка товаров в админке.

Скрытые товары должны быть доступны владельцу в отдельном списке в админке.

Черновики должны быть доступны владельцу в отдельном списке в админке.

## 9. Поиск в админке

Владелец должен иметь возможность найти товар по названию.

Поиск нужен, чтобы быстро менять цену, фото, вкусы или состояние товара.

Поиск в админке работает по названию товара.

## 10. Ручная сортировка товаров

Владелец должен иметь возможность вручную менять порядок товаров в разделе **Все напитки** через перетаскивание.

Владелец должен иметь возможность вручную менять порядок товаров внутри каждой категории через перетаскивание.

Эти порядки должны использоваться в клиентском каталоге.

Ручная сортировка в **Все напитки** нужна, чтобы владелец мог поднять ходовые, важные или приоритетные товары выше на первом экране каталога.

Ручная сортировка внутри категории нужна, чтобы владелец мог отдельно настроить порядок товаров в конкретной категории.

Порядок товаров в **Все напитки** и порядок товаров внутри категории настраиваются отдельно и могут отличаться.

Порядок показа не редактируется как отдельное числовое поле товара.

Если владелец не менял порядок вручную, новый товар попадает в конец раздела **Все напитки** и в конец своей категории.

Если владелец меняет категорию товара, товар исчезает из старой категории, а список старой категории смыкается без пустого места.

После смены категории товар попадает в конец новой категории, если владелец не переставил его вручную.

## 11. Основной сценарий добавления товара

1. Владелец входит в админку.
2. Владелец открывает список товаров.
3. Владелец выбирает добавление товара.
4. Владелец заполняет данные товара.
5. Владелец добавляет фото.
6. Владелец выбирает категорию.
7. Владелец сохраняет товар.
8. Товар появляется в клиентском каталоге, если он не скрыт, не является черновиком и у него заполнены обязательные данные.

## 12. Основной сценарий редактирования товара

1. Владелец входит в админку.
2. Владелец находит товар в списке или через поиск.
3. Владелец открывает редактирование товара.
4. Владелец меняет нужные поля.
5. Владелец сохраняет изменения.
6. Изменения отражаются в клиентском каталоге, если товар видим клиенту и не является черновиком.

## 13. Нестандартные ситуации

Нужно предусмотреть:

- владелец добавляет товар без основного фото;
- владелец добавляет товар без цены;
- владелец добавляет товар без количества штук в одной уп;
- владелец сохраняет товар как черновик;
- владелец не выбрал категорию;
- владелец добавляет категорию;
- владелец переименовывает категорию;
- владелец удаляет пустую категорию;
- владелец пытается удалить категорию, в которой есть товары;
- владелец меняет порядок категорий;
- владелец добавляет вкус без названия;
- владелец отмечает все вкусы товара как "нет в наличии", из-за чего товар становится видимым, но недоступным для заказа;
- владелец хочет скрыть товар;
- владелец хочет вернуть скрытый товар;
- владелец хочет удалить товар;
- владелец открывает список черновиков;
- владелец перетаскивает товар в разделе "Все напитки";
- владелец перетаскивает товар внутри категории;
- владелец ищет товар, но ничего не найдено;
- владелец пытается сохранить пустое название.

## 14. Правила первой версии

- Владелец управляет товарами через админку.
- Категории работают по правилам раздела 5.
- Обязательные данные товара, фото, цена, вкусы и статусы работают по правилам разделов 4, 6, 7, 7.1 и 8.
- Сортировка товаров работает по правилам раздела 10.
- Поиск работает по названию товара.
- Точные остатки в штуках не ведутся.
- Скрытые товары должны быть доступны в отдельном списке в админке.
- Черновики должны быть доступны в отдельном списке в админке.
- Перед скрытием товара нужно подтверждение.
- Перед удалением товара нужно подтверждение.
- Владелец может удалить товар из админки.
