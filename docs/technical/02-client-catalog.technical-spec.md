# Technical Spec: Client Catalog v0.1

## 1. Назначение

Этот документ описывает техническую работу клиентского каталога.

Он опирается на feature spec `01-client-catalog.feature-spec.md`.

## 2. Главная идея

Клиентский каталог - публичная часть сайта.

Он получает актуальные товары, категории, фото, цены, статусы и вкусы из серверной части.

Клиент не должен видеть скрытые товары, черновики и удаленные товары.

Клиент не редактирует данные каталога.

## 3. Маршруты

Основной маршрут:

- `/` - каталог.

Каталог может работать через параметры адреса:

- `?category={categoryId}` - выбранная категория;
- `?search={query}` - поиск внутри выбранного фильтра.

Фильтр **Все напитки** не обязан иметь `categoryId`. Его можно считать режимом по умолчанию.

## 4. Серверные данные для каталога

Клиентскому каталогу нужны данные:

- список категорий;
- список видимых товаров;
- вкусы товаров;
- эффективная цена;
- эффективное фото;
- статус доступности товара;
- порядок показа.

Сервер должен отдавать только данные, которые можно показывать клиенту.

Скрытые товары, черновики и удаленные товары не должны уходить в клиентский ответ.

## 5. Категории и фильтр Все напитки

Сервер отдает категории в порядке `categories.sort_order`.

Фильтр **Все напитки** добавляется на клиенте или сервере как системный фильтр.

**Все напитки**:

- всегда первый;
- не хранится как категория;
- не имеет страницы редактирования в админке;
- показывает все видимые товары;
- использует порядок `products.all_drinks_sort_order`.

Категория:

- показывает только товары с выбранным `category_id`;
- использует порядок `products.category_sort_order`.

Пустую категорию можно показывать клиенту.

## 6. Получение товаров

Для каталога нужен технический запрос:

```text
GET /api/catalog?category={categoryId}&search={query}
```

Если `category` не указан, сервер возвращает товары для фильтра **Все напитки**.

Если `category` указан, сервер возвращает товары только этой категории.

Если `search` указан, сервер фильтрует товары внутри выбранного фильтра.

Поиск работает только по названию товара.

Поиск не ищет по названию вкуса.

## 7. DTO товара для клиента

Клиенту не нужно получать все поля из базы.

Черновой формат товара:

```text
ProductForClient
- id
- name
- priceRub
- packQuantity
- imageUrl
- status
- isVisible
- isOrderable
- hasFlavorChoice
- flavors[]
```

Черновой формат вкуса:

```text
FlavorForClient
- id
- name
- priceRub
- imageUrl
- isOutOfStock
- isOrderable
- sortOrder
```

`isVisible` можно не отдавать, если сервер уже фильтрует невидимые товары.

`isOrderable` полезно отдавать явно, чтобы интерфейс не дублировал сложную логику.

## 8. Цена на карточке

Для товара без выбора вкуса карточка показывает базовую цену.

Для товара с выбором вкуса карточка до выбора вкуса показывает цену первого вкуса по порядку.

Если у первого вкуса нет отдельной цены, показывается базовая цена товара.

После выбора вкуса цена карточки меняется на эффективную цену выбранного вкуса.

Если выбранный вкус недоступен, кнопка добавления в заказ должна быть недоступна.

## 9. Фото на карточке

Для товара без выбора вкуса показывается основное фото товара.

Для товара с выбором вкуса до выбора вкуса показывается фото первого вкуса, если оно есть.

Если у первого вкуса нет фото, показывается основное фото товара.

После выбора вкуса фото меняется на фото вкуса, если оно есть.

Если у выбранного вкуса нет фото, показывается основное фото товара.

## 10. Доступность товара

Товар можно добавить в заказ только если `isOrderable = true`.

Товар с `status = out_of_stock`:

- виден клиенту;
- визуально слабее доступного товара;
- не может быть добавлен в заказ.

Товар с выбором вкуса:

- если выбран доступный вкус, его можно добавить в заказ;
- если выбран недоступный вкус, его нельзя добавить в заказ;
- если все вкусы недоступны, вся карточка считается недоступной для заказа.

Состояние "все вкусы недоступны" вычисляется на сервере или в общем доменном модуле.

## 11. Добавление в корзину

Каталог не отправляет заказ.

Каталог только добавляет позицию в корзину.

Для добавления в корзину нужен минимальный набор:

- `productId`;
- `flavorId`, если выбран вкус;
- `quantity = 1`.

Если у товара есть выбор вкуса, клиент должен выбрать вкус до добавления.

Если у товара нет выбора вкуса, `flavorId` не нужен.

## 12. Поиск

Поиск должен быть нечувствителен к регистру.

Поиск действует внутри выбранного фильтра:

- **Все напитки** - поиск по всем видимым товарам;
- категория - поиск только по товарам этой категории.

Поиск не должен показывать скрытые товары, черновики и удаленные товары.

Товары **нет в наличии** могут попадать в поиск, но не могут добавляться в заказ.

## 13. Пустые состояния

Если в каталоге нет видимых товаров, клиент видит пустое состояние каталога.

Если в категории нет видимых товаров, клиент видит пустое состояние категории.

Если поиск ничего не нашел, клиент видит пустое состояние поиска.

Тексты пустых состояний берутся из feature spec `07-empty-and-error-states`.

## 14. Производительность

Каталог должен быстро открываться на телефоне.

Для первой версии допустимо загружать все видимые товары сразу, если ассортимент небольшой.

Если ассортимент станет большим, нужно добавить постраничную загрузку или виртуализацию списка.

Фото должны быть оптимизированы, чтобы каталог не тормозил на мобильном интернете.

## 15. Вопросы для подтверждения

1. Нужно ли делать отдельные URL для категорий, или достаточно параметра `?category=`?
2. Загружаем все товары сразу или делаем постепенную загрузку, если ассортимент большой?
3. До выбора вкуса показывать фото первого вкуса, если оно есть, или всегда основное фото товара?
