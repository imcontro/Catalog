# Technical Spec: Deployment And Operations v0.1

## 1. Назначение

Этот документ описывает технические правила размещения, окружений, бэкапов и эксплуатации проекта.

Он нужен, чтобы каталог был доступен клиентам по ссылке, а владелец мог заходить в админку с нужных компьютеров.

## 2. Главная идея

Проект должен быть размещен онлайн на Vercel.

Клиенты открывают публичную ссылку на каталог.

Владелец открывает админку по адресу сайта и входит по логину и паролю.

Админка не привязана к одному конкретному компьютеру. Она доступна с любого устройства, где есть адрес админки и верные данные входа.

## 3. Окружения

Нужно минимум два окружения приложения:

- разработка - локальный запуск для проверки изменений;
- продакшен - сайт на Vercel для реальных клиентов.

В первой версии текущий чистый Supabase-проект используется как основной рабочий Supabase для каталога.

Отдельный тестовый Supabase-проект не обязателен и не создается только ради деплоя.

Локальная разработка может использовать тот же рабочий Supabase, если владелец подтвердил, что база чистая и готова к запуску. При этом нельзя выполнять случайные тесты, массовые удаления или рискованные изменения без отдельного плана и бэкапа.

Отдельный тестовый Supabase-проект можно создать позже отдельным решением, если понадобятся рискованные эксперименты или крупные проверки, которые нельзя безопасно выполнять на рабочей базе.

## 4. Продакшен

Продакшен размещается на Vercel и должен иметь:

- публичный домен или стабильную ссылку;
- HTTPS;
- базу данных Supabase;
- хранилище фото;
- переменные окружения;
- возможность делать бэкапы.

Клиентский каталог должен открываться без входа.

Админские страницы должны требовать вход.

Домен будет подключаться через Vercel. Конкретный домен владелец выбирает отдельно.

## 5. Переменные окружения

Нужны настройки:

```text
DATABASE_URL
SUPABASE_URL
SUPABASE_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY
SUPABASE_STORAGE_BUCKET
ADMIN_LOGIN
ADMIN_PASSWORD_HASH
WHATSAPP_PHONE
DELIVERY_FREE_THRESHOLD_RUB
PUBLIC_SITE_URL
SESSION_SECRET
```

`DATABASE_URL` должен указывать на Supabase Postgres.

`SUPABASE_STORAGE_BUCKET` для первой версии: `product-images`.

`WHATSAPP_PHONE` для первой версии: `79380046199`.

Фото хранятся в Supabase Storage. Подробные правила Supabase-переменных описаны в `08-supabase.technical-spec.md`.

## 6. База данных

Для продакшена используется Supabase Postgres.

Перед запуском первой версии нужно убедиться, что миграции уже применены к рабочему Supabase.

Стартовые категории создаются по правилам `01-data-model.technical-spec.md` и `08-supabase.technical-spec.md`.

База должна регулярно сохраняться в бэкап через возможности Supabase или отдельный экспорт.

## 7. Бэкапы

Нужно бэкапить Supabase Postgres, Supabase Storage и безопасную копию настроек окружения.

Без бэкапа фото владелец может потерять каталог при проблеме с сервером.

За бэкапы Supabase после запуска отвечает владелец проекта.

Подробные правила Supabase-бэкапов описаны в `08-supabase.technical-spec.md`.

## 8. Деплой

Деплой не должен удалять загруженные фото.

Так как фото хранятся в Supabase Storage, деплой приложения на Vercel не должен удалять загруженные фото.

После деплоя нужно проверить:

- каталог открывается;
- категории отображаются;
- товары отображаются;
- фото загружаются;
- корзина работает;
- WhatsApp открывается;
- админка открывается после входа;
- товар можно добавить или изменить;
- фото можно загрузить.

## 9. Логи и ошибки

Продакшен должен фиксировать технические ошибки:

- ошибки сервера;
- ошибки загрузки фото;
- ошибки входа в админку;
- ошибки работы с базой;
- ошибки генерации WhatsApp-ссылки.

Логи не должны содержать пароль администратора.

Логи не должны хранить лишние персональные данные клиента.

## 10. Доступ к админке

Админка доступна по логину и паролю.

В клиентском каталоге не показывается ссылка на админку.

Если нужно ограничить админку сильнее, позже можно добавить:

- ограничение по IP;
- отдельные аккаунты;
- двухфакторную авторизацию.

В первую версию это не входит.

## 11. Проверка перед запуском

Перед реальным запуском нужно проверить:

- сайт открывается с телефона;
- сайт открывается с компьютера;
- каталог доступен без входа;
- админка требует вход;
- неверный пароль не открывает админку;
- категории можно менять;
- товар можно создать;
- товар без обязательных данных не виден клиенту;
- фото товара отображается;
- вкус товара можно выбрать;
- недоступный вкус нельзя добавить в заказ;
- корзина считает сумму;
- подсказка доставки работает от суммы 8000 рублей;
- адрес обязателен;
- способ оплаты обязателен;
- WhatsApp-сообщение формируется корректно.

## 12. Принятые решения

1. Домен будет подключаться через Vercel. Конкретный домен владелец решит отдельно.
2. За бэкапы Supabase после запуска отвечает владелец проекта.
3. Текущий чистый Supabase-проект используем как основной рабочий Supabase первой версии и не переносим данные в отдельный проект только ради запуска.
4. Отдельный тестовый Supabase-проект не обязателен; его можно создать позже отдельным решением для рискованных экспериментов или крупных проверок.
