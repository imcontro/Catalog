# Technical Spec: Overview v0.1

## 1. Назначение

Этот документ описывает общий технический подход к проекту **Каталог NapitkiBerkat**.

Он не описывает дизайн интерфейса и не является планом разработки.

Задача technical specs - зафиксировать, как feature specs будут превращаться в работающую систему:

- из каких технических частей состоит проект;
- где хранятся товары, категории, вкусы и фото;
- какие страницы и серверные части нужны;
- как работает клиентский каталог;
- как работает корзина и отправка в WhatsApp;
- как работает админка;
- как проект будет доступен клиентам и владельцу.

## 3. Общая архитектура

Проект должен быть одной веб-системой с двумя зонами:

- публичный клиентский каталог;
- закрытая админка.

Клиентский каталог открывается по ссылке и доступен без входа.

Админка доступна только после входа по общему логину и паролю.

Клиентский каталог и админка используют одну общую базу данных.

Фото товаров загружаются через админку и используются в клиентском каталоге.

Заказы в первой версии не сохраняются как отдельные записи в базе данных. Основной канал заказа - WhatsApp-сообщение, которое клиент отправляет работнику магазина.

## 4. Черновой стек

Для первой версии подходит стек:

- веб-приложение: React / Next.js / TypeScript;
- серверная часть: API внутри того же приложения;
- база данных: Supabase Postgres для продакшена;
- разработка до запуска: отдельный тестовый Supabase-проект;
- реальный запуск: отдельный боевой Supabase-проект;
- работа с базой: ORM;
- хранение фото: Supabase для базы + Supabase Storage для фото;
- авторизация админки: серверная сессия через cookie.

Supabase использует PostgreSQL под капотом, поэтому правила модели данных остаются PostgreSQL-совместимыми.

Тестовый Supabase нужен, чтобы во время разработки спокойно проверять админку, товары, цены, фото, вкусы, корзину и WhatsApp без риска испортить реальные данные.

Боевой Supabase нужен для настоящего каталога, где будут реальные товары, цены и фото.

Это черновое техническое решение. Его можно изменить до work plans, если выбранный хостинг или бюджет потребуют уточнения стека.

## 5. Основные страницы

Публичные страницы:

- `/` - клиентский каталог;
- `/checkout` - оформление заказа.

Админские страницы:

- `/admin/login` - вход в админку;
- `/admin` - главный экран админки;
- `/admin/products` - список товаров;
- `/admin/products/new` - добавление товара;
- `/admin/products/{id}` - редактирование товара;
- `/admin/categories` - управление категориями;
- `/admin/sorting/all` - сортировка товаров в **Все напитки**;
- `/admin/sorting/category/{id}` - сортировка товаров внутри категории;
- `/admin/drafts` - черновики;
- `/admin/hidden` - скрытые товары.

В клиентском каталоге не должно быть видимой ссылки на админку.

## 6. Основные технические модули

Проект делится на модули:

- каталог;
- категории;
- товары;
- вкусы;
- корзина;
- оформление заказа;
- доставка;
- WhatsApp-сообщение;
- админская авторизация;
- управление товарами;
- управление фото;
- пустые и ошибочные состояния.

Каждый модуль должен иметь отдельные функции или сервисы, чтобы правила не размазывались по интерфейсу.

## 7. Данные первой версии

В базе данных нужны сущности:

- категория;
- товар;
- вкус товара;
- фото;
- сессия администратора.

Отдельная сущность заказа в первой версии не нужна.

Отдельная сущность клиента в первой версии не нужна.

Остатки товара в штуках не хранятся.

Разные цены для разных клиентов не хранятся.

## 8. Главные технические правила

Клиент видит только товары, которые:

- не являются черновиками;
- не скрыты;
- не удалены;
- имеют основное фото;
- имеют цену;
- имеют количество штук в одной уп;
- имеют категорию.

Товар с отметкой **нет в наличии** виден клиенту, но недоступен для добавления в заказ.

Если у товара все вкусы отмечены как **нет в наличии**, это вычисляемое состояние. Товар виден клиенту, но недоступен для заказа.

Скрытые товары, удаленные товары и черновики не должны попадать в клиентский каталог и клиентский поиск.

Корзина хранится на стороне клиента.

Перед отправкой в WhatsApp корзина должна быть сверена с актуальными данными каталога.

## 9. Что не входит в техническую первую версию

В техническую первую версию не входят:

- личные кабинеты клиентов;
- регистрация клиентов;
- сохранение заказов в CRM;
- онлайн-оплата;
- расчет точной стоимости доставки;
- автоматическая проверка города в адресе;
- точные складские остатки;
- разные админские роли;
- сложная аналитика;
- интеграции со складом;
- промокоды и скидки.
