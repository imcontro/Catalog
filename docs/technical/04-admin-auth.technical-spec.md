# Technical Spec: Admin Auth v0.1

## 1. Назначение

Этот документ описывает техническую работу входа в админку.

Он опирается на feature spec `05-admin-auth.feature-spec.md`.

## 2. Общая идея

Админка закрыта от клиентов.

Для первой версии используется один общий логин и один общий пароль.

Сложная система ролей не нужна.

Клиентский каталог не показывает ссылку на админку.

## 3. Маршруты

Публичный маршрут входа:

- `/admin/login`

Закрытые маршруты:

- `/admin`
- `/admin/products`
- `/admin/products/new`
- `/admin/products/{id}`
- `/admin/categories`
- `/admin/sorting/all`
- `/admin/sorting/category/{id}`
- `/admin/drafts`
- `/admin/hidden`

Если владелец открывает закрытый маршрут без сессии, его нужно отправить на `/admin/login`.

## 4. Хранение логина и пароля

В первой версии логин администратора можно хранить в переменных окружения:

```text
ADMIN_LOGIN
ADMIN_PASSWORD_HASH
```

Пароль нельзя хранить в открытом виде.

При входе введенный пароль сравнивается с хешем.

Смена пароля через админку в первой версии не нужна.

Владелец сам хранит общий пароль в удобном для себя месте.

## 5. Сессия

После успешного входа сервер создает сессию.

Сессия хранится в cookie:

- `httpOnly`;
- `secure` на продакшене;
- `sameSite`;
- с ограниченным сроком жизни.

Сервер хранит хеш токена сессии в таблице `admin_sessions`.

После выхода сессия помечается как закрытая.

## 6. Проверка доступа

Все админские страницы и админские API должны проверять сессию.

Проверка должна выполняться на сервере.

Клиентская проверка интерфейса не считается защитой.

Если сессии нет или она недействительна:

- админская страница переводит на `/admin/login`;
- админский API возвращает ошибку доступа.

## 7. Вход

Форма входа содержит:

- логин;
- пароль;
- кнопку входа.

Технический запрос:

```text
POST /api/admin/login
```

Если данные верные:

- создается сессия;
- владелец попадает в админку.

Если данные неверные:

- сессия не создается;
- показывается общая ошибка.

Ошибка не должна говорить отдельно, что неверно: логин или пароль.

## 8. Выход

Технический запрос:

```text
POST /api/admin/logout
```

После выхода:

- текущая сессия становится недействительной;
- cookie удаляется;
- владелец попадает на страницу входа.

Кнопка "Назад" в браузере не должна открыть рабочую админку без новой проверки сессии.

## 9. Ограничения первой версии

В первой версии не нужны:

- регистрация новых администраторов;
- разные роли;
- отдельные аккаунты работников;
- восстановление пароля через email;
- двухфакторная авторизация;
- автоматический выход после бездействия.

## 10. Безопасность

Минимальные правила:

- не хранить пароль открытым текстом;
- использовать HTTPS на продакшене;
- защищать админские API серверной проверкой сессии;
- не показывать админскую ссылку в клиентском каталоге;
- не раскрывать детали ошибки входа;
- ограничить размер полей логина и пароля.

## 11. Принятые решения

1. Отдельный сложный или скрытый адрес админки не нужен. Достаточно, что ссылка на админку не показывается в клиентском каталоге.
2. Админка остается доступна по маршрутам `/admin` и `/admin/login`.
3. Владелец сам хранит общий пароль в удобном для себя месте.
4. Смену пароля через админку в первую версию не добавляем.
