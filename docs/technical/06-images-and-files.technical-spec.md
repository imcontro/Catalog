# Technical Spec: Images And Files v0.1

## 1. Назначение

Этот документ описывает техническую работу с фото товаров и вкусов.

Фото обязательны для клиентского каталога, поэтому хранение и обработка изображений - отдельная техническая часть проекта.

## 2. Где используются фото

Фото используются:

- в карточке товара в клиентском каталоге;
- в списке товаров админки;
- в форме редактирования товара;
- у вкусов товара, если у вкуса есть отдельное фото.

Основное фото товара обязательно для клиентского каталога.

Фото вкуса не обязательно.

## 3. Загрузка фото

Фото загружается через админку.

Технический запрос:

```text
POST /api/admin/images
```

Запрос должен принимать файл изображения.

После загрузки сервер:

- проверяет тип файла;
- проверяет размер файла;
- сохраняет файл;
- создает запись в таблице `images`;
- возвращает `imageId` и публичную ссылку.

## 4. Допустимые форматы

Для первой версии допустимы:

- JPG;
- PNG;
- WebP.

HEIC и другие форматы можно не поддерживать в первой версии, если это усложняет обработку.

## 5. Размер файла

Нужно ограничить размер загружаемого файла.

Черновое ограничение:

```text
до 5 МБ на файл
```

Если файл больше лимита, админка должна показать понятную ошибку.

## 6. Обработка изображения

После загрузки изображение желательно обработать:

- исправить ориентацию, если возможно;
- уменьшить слишком большое изображение;
- создать оптимизированный вариант для каталога;
- сохранить размеры изображения.

Черновые размеры:

- основное изображение: до 1200px по большей стороне;
- миниатюра для админки: до 300px по большей стороне.

Если обработка изображений будет усложнять первую версию, можно начать с сохранения оригинала и ограничить размер файла, но каталог должен оставаться быстрым.

## 7. Хранение файлов

Есть два возможных варианта.

### 7.1. Серверное хранение

Фото хранятся в папке приложения, например:

```text
uploads/products
```

Плюсы:

- проще стартовать;
- меньше внешних сервисов.

Минусы:

- нужно следить, чтобы хостинг не удалял файлы при деплое;
- нужны бэкапы папки с фото.

### 7.2. Объектное хранилище

Фото хранятся во внешнем хранилище.

Плюсы:

- надежнее для продакшена;
- проще делать деплой без риска потерять фото.

Минусы:

- больше настроек;
- возможна отдельная оплата.

## 8. Черновое решение для первой версии

До выбора хостинга решение остается открытым.

Если проект будет размещаться на VPS, можно начать с серверного хранения и обязательных бэкапов.

Если проект будет размещаться на платформе, где файловая система временная, нужно использовать объектное хранилище.

## 9. Привязка фото

Основное фото товара:

- хранится в `products.main_image_id`;
- обязательно для видимости товара клиенту.

Фото вкуса:

- хранится в `product_flavors.image_id`;
- необязательно;
- если отсутствует, используется основное фото товара.

## 10. Удаление и замена фото

При замене фото товар или вкус получает новый `image_id`.

Старое фото не нужно удалять сразу, если оно может использоваться где-то еще.

Нужна отдельная техническая задача для очистки неиспользуемых фото.

Удаление товара не должно сразу удалять фото, если используется мягкое удаление через `deleted_at`.

## 11. Безопасность

Нужно проверять:

- что файл действительно изображение;
- что тип файла разрешен;
- что размер не превышает лимит;
- что имя файла не используется напрямую как путь;
- что загружать фото может только админ.

Публичные ссылки на фото доступны клиентам.

Админские API загрузки фото доступны только после входа.
