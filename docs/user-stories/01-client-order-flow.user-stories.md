# User Stories Spec: Client Order Flow v0.1

## 1. Назначение

Этот документ описывает истории клиента: от открытия каталога по ссылке до отправки заказа в WhatsApp.

Главная цель клиента - быстро увидеть ассортимент и цены, выбрать напитки, понять условия доставки и отправить понятный заказ.

## US-CL-01. Открыть каталог по ссылке

История:

```text
Как клиент,
я хочу открыть каталог по ссылке,
чтобы быстро увидеть ассортимент NapitkiBerkat без переписки и ожидания ответа.
```

Основной сценарий:

1. Клиент получает ссылку на каталог.
2. Клиент открывает ссылку на телефоне или компьютере.
3. Сайт открывает публичный клиентский каталог без входа.
4. Клиент видит фильтр **Все напитки** и товары из всего видимого каталога.

Критерии приемки:

- каталог открывается без логина и пароля;
- первым выбран фильтр **Все напитки**;
- клиент видит только видимые товары;
- скрытые товары, черновики и удаленные товары не показываются;
- в клиентском каталоге нет видимой ссылки или кнопки перехода в админку;
- мобильный телефон является главным устройством для проверки удобства.

## US-CL-02. Смотреть ассортимент по категориям

История:

```text
Как клиент,
я хочу переключаться между категориями,
чтобы быстро найти нужный тип напитков.
```

Основной сценарий:

1. Клиент открывает каталог.
2. Клиент видит фильтр **Все напитки** первым.
3. После него клиент видит категории, заданные владельцем.
4. Клиент выбирает категорию.
5. Сайт показывает товары выбранной категории.

Критерии приемки:

- **Все напитки** не является обычной категорией товара;
- **Все напитки** нельзя удалить или переименовать через клиентский интерфейс;
- категории показываются в порядке, заданном владельцем;
- товары в **Все напитки** показываются в отдельном ручном порядке;
- товары внутри категории показываются в ручном порядке этой категории;
- пустую категорию можно показать клиенту с понятным пустым состоянием.

## US-CL-03. Найти товар по названию

История:

```text
Как клиент,
я хочу найти товар по названию,
чтобы не просматривать весь ассортимент вручную.
```

Основной сценарий:

1. Клиент вводит название или часть названия товара в поиск.
2. Сайт ищет товар внутри выбранного фильтра.
3. Клиент видит подходящие товары.

Критерии приемки:

- поиск работает только по названию товара;
- поиск не ищет по названию вкуса;
- если выбран фильтр **Все напитки**, поиск идет по всем видимым товарам;
- если выбрана категория, поиск идет только внутри этой категории;
- поиск не показывает скрытые товары, черновики и удаленные товары;
- товары **нет в наличии** могут попадать в поиск, но не могут быть добавлены в заказ;
- если ничего не найдено, клиент видит понятное пустое состояние.

## US-CL-04. Понять карточку товара

История:

```text
Как клиент,
я хочу сразу понять товар по карточке,
чтобы решить, подходит ли он мне для заказа.
```

Основной сценарий:

1. Клиент смотрит карточку товара.
2. Клиент видит фото, название, цену и количество штук в одной уп.
3. Если у товара есть вкусы, клиент видит выбор вкуса.
4. Клиент понимает, можно ли добавить товар в заказ.

Критерии приемки:

- карточка показывает фото товара;
- карточка показывает название товара;
- объем, тара или формат указываются в названии, если они важны;
- отдельного поля объема в первой версии нет;
- карточка показывает цену одной уп;
- карточка показывает количество штук в одной уп в формате `{число} шт в уп`;
- товар **нет в наличии** виден, но визуально слабее и недоступен для заказа;
- товар без основного фото, цены или количества штук в одной уп клиенту не показывается.

## US-CL-05. Выбрать вкус товара

История:

```text
Как клиент,
я хочу выбрать вкус у товара,
чтобы заказать нужный вариант напитка.
```

Основной сценарий:

1. Клиент видит одну карточку товара с вариантами вкусов.
2. Клиент выбирает нужный вкус.
3. Фото и цена меняются, если у выбранного вкуса есть отдельное фото или отдельная цена.
4. Клиент добавляет доступный вкус в заказ.

Критерии приемки:

- товар с несколькими вкусами остается одной карточкой;
- до выбора вкуса карточка показывает цену первого вкуса по порядку;
- до выбора вкуса карточка показывает фото первого вкуса, если оно есть;
- если у вкуса нет отдельного фото, используется основное фото товара;
- если у вкуса нет отдельной цены, используется базовая цена товара;
- недоступный вкус виден, но его нельзя выбрать для заказа;
- если первый вкус недоступен, но другой вкус доступен, карточка остается видимой и клиент может выбрать доступный вкус;
- если все вкусы недоступны, товар виден, но недоступен для заказа.

## US-CL-06. Добавить товары в заказ

История:

```text
Как клиент,
я хочу добавлять напитки в заказ,
чтобы собрать нужный список без ручного написания в WhatsApp.
```

Основной сценарий:

1. Клиент выбирает доступный товар.
2. Если у товара есть вкусы, клиент выбирает вкус.
3. Клиент добавляет товар в корзину.
4. Если клиент добавляет тот же товар с тем же вкусом повторно, количество увеличивается.

Критерии приемки:

- товар без выбора вкуса добавляется без дополнительного выбора;
- товар с выбором вкуса нельзя добавить, пока вкус не выбран;
- один товар с разными вкусами считается разными позициями корзины;
- повторное добавление того же товара с тем же вкусом увеличивает количество;
- единица заказа - упаковка, на сайте отображается как **уп**;
- количество нельзя вводить текстом вручную.

## US-CL-07. Управлять корзиной

История:

```text
Как клиент,
я хочу менять количество товаров в корзине плюсом и минусом,
чтобы быстро собрать правильный заказ.
```

Основной сценарий:

1. Клиент открывает корзину.
2. Клиент видит выбранные позиции.
3. Клиент увеличивает или уменьшает количество через плюс и минус.
4. Клиент удаляет отдельную позицию или очищает всю корзину, если нужно.
5. Клиент видит общую сумму товаров.

Критерии приемки:

- минимальное количество позиции - 1 уп;
- минус у позиции с количеством 1 уп удаляет позицию из корзины;
- у каждой позиции есть отдельная кнопка удаления;
- в корзине есть отдельная кнопка очистки всей корзины;
- вкус товара нельзя изменить прямо в корзине;
- чтобы выбрать другой вкус, клиент удаляет позицию и добавляет товар заново;
- общая сумма товаров видна всегда, как в корзине маркетплейса;
- сумма считается только по доступным позициям.

## US-CL-08. Видеть мотивацию бесплатной доставки

История:

```text
Как клиент,
я хочу заранее видеть подсказку по бесплатной доставке,
чтобы понимать, сколько осталось добавить до бесплатной доставки по г. Грозный.
```

Основной сценарий:

1. Клиент добавляет товары в корзину.
2. Сайт считает сумму доступных позиций.
3. Если сумма меньше 8000 рублей, клиент видит остаток до бесплатной доставки.
4. Если сумма от 8000 рублей, клиент видит, что доставка бесплатна по г. Грозный.

Критерии приемки:

- порог бесплатной доставки - 8000 рублей;
- порог считается только по доступным позициям;
- недоступные позиции не участвуют в пороге;
- если сумма меньше 8000 рублей, текст: `До бесплатной доставки по г. Грозный осталось {остаток} руб.`;
- если сумма от 8000 рублей включительно, текст: `Доставка: бесплатно по г. Грозный`;
- сайт не проверяет город в адресе;
- точная стоимость доставки до 8000 рублей не рассчитывается.

## US-CL-09. Оформить заказ

История:

```text
Как клиент,
я хочу указать адрес и способ оплаты,
чтобы отправить магазину полный заказ без лишних уточнений.
```

Основной сценарий:

1. Клиент открывает оформление заказа.
2. Клиент проверяет выбранные товары и сумму.
3. Клиент вводит адрес доставки.
4. Клиент выбирает способ оплаты.
5. Клиент видит итоговую строку доставки.

Критерии приемки:

- адрес доставки обязателен;
- в поле адреса есть пример: `Грозный ул. Назабраева 92`;
- имя клиента отдельно не спрашивается;
- телефон клиента отдельно не спрашивается;
- способ оплаты обязателен;
- способы оплаты: наличные и перевод;
- онлайн-оплаты на сайте нет;
- если сумма доступных позиций от 8000 рублей, доставка показывается как `Доставка: бесплатно по г. Грозный`;
- если сумма меньше 8000 рублей, доставка показывается как `Доставка: стоимость сообщим в WhatsApp по тарифу`.

## US-CL-10. Отправить заказ в WhatsApp

История:

```text
Как клиент,
я хочу нажать "Отправить в WhatsApp",
чтобы передать магазину готовый заказ одним сообщением.
```

Основной сценарий:

1. Клиент нажимает "Отправить в WhatsApp".
2. Сайт проверяет корзину, адрес и способ оплаты.
3. Сайт формирует WhatsApp-сообщение.
4. Открывается WhatsApp с готовым текстом.
5. Клиент отправляет сообщение работнику магазина.

Критерии приемки:

- сообщение начинается с текста `Добрый день! Хочу сделать заказ!`;
- в сообщение попадают только доступные позиции;
- строка товара с вкусом выглядит компактно: `Название товара вкус - 1уп`;
- строка товара без вкуса выглядит компактно: `Название товара - 1уп`;
- источник заказа в сообщение не добавляется;
- дата и время не добавляются;
- фраза подтверждения заказа не добавляется;
- сумма товаров считается только по доступным позициям;
- после перехода по WhatsApp-ссылке корзина очищается;
- если WhatsApp не открылся, клиент видит официальное сообщение об ошибке.

## US-CL-11. Увидеть изменения после добавления в корзину

История:

```text
Как клиент,
я хочу видеть актуальные цены и доступность,
чтобы случайно не отправить устаревший заказ.
```

Основной сценарий:

1. Клиент добавил товар в корзину.
2. Владелец изменил цену, наличие, скрытие или удаление товара.
3. Клиент открывает корзину или отправляет заказ.
4. Сайт актуализирует корзину.

Критерии приемки:

- если цена изменилась, корзина показывает актуальную цену и предупреждение;
- если товар или вкус стал **нет в наличии**, позиция остается видимой, но не участвует в сумме и отправке;
- клиент видит предупреждение, что недоступная позиция не попадет в WhatsApp-сообщение;
- если товар скрыт, позиция исчезает из корзины;
- если товар удален, позиция исчезает из корзины;
- заказ нельзя отправить, если в корзине нет доступных позиций.
