# User Stories Spec: Store Worker WhatsApp v0.1

## 1. Назначение

Этот документ описывает истории работника магазина, который получает заказ в WhatsApp.

Главная цель работника - быстро понять заказ без дополнительной расшифровки и начать обработку в чате.

## US-WK-01. Получить понятный заказ

История:

```text
Как работник магазина,
я хочу получить понятное WhatsApp-сообщение,
чтобы быстро понять, что клиент хочет заказать.
```

Основной сценарий:

1. Клиент собирает заказ на сайте.
2. Клиент нажимает "Отправить в WhatsApp".
3. Работник получает сообщение в WhatsApp.
4. Работник читает список товаров, сумму, доставку, адрес и оплату.

Критерии приемки:

- сообщение начинается с `Добрый день! Хочу сделать заказ!`;
- список товаров компактный;
- у товара с вкусом вкус указан в строке товара;
- у товара без вкуса вкус не добавляется;
- количество отображается в формате **уп**;
- сумма товаров указана отдельно;
- источник заказа не указывается;
- дата и время не указываются;
- лишняя фраза подтверждения заказа не добавляется.

## US-WK-02. Быстро разобрать товары

История:

```text
Как работник магазина,
я хочу видеть товары короткими строками,
чтобы быстро собрать заказ без лишнего чтения.
```

Основной сценарий:

1. Работник открывает WhatsApp-сообщение.
2. Работник видит блок товаров.
3. Работник по каждой строке понимает товар, вкус и количество уп.

Критерии приемки:

- строка товара с вкусом выглядит как `Название товара вкус - 1уп`;
- строка товара без вкуса выглядит как `Название товара - 1уп`;
- в строке товара не расписываются отдельные поля "Количество", "Цена" и "Сумма";
- объем, тара или формат товара входят в название, если они важны;
- отдельный объем товара в WhatsApp не расписывается;
- в сообщение попадают только доступные позиции.

## US-WK-03. Понять доставку и оплату

История:

```text
Как работник магазина,
я хочу видеть адрес, доставку и способ оплаты,
чтобы сразу понимать дальнейшую обработку заказа.
```

Основной сценарий:

1. Работник получает заказ.
2. Работник смотрит адрес доставки.
3. Работник смотрит строку доставки.
4. Работник смотрит способ оплаты.

Критерии приемки:

- адрес доставки есть в сообщении;
- способ оплаты есть в сообщении;
- если сумма доступных позиций от 8000 рублей, доставка указана как `Доставка: бесплатно по г. Грозный`;
- если сумма меньше 8000 рублей, доставка указана как `Доставка: стоимость сообщим в WhatsApp по тарифу`;
- сайт не проверяет город в адресе;
- точная стоимость доставки до 8000 рублей уточняется в WhatsApp.

## US-WK-04. Обрабатывать заказ только в WhatsApp

История:

```text
Как работник магазина,
я хочу работать с заказом в WhatsApp,
чтобы первая версия не требовала отдельной CRM или панели заказов.
```

Основной сценарий:

1. Клиент отправляет заказ в WhatsApp.
2. Работник получает сообщение.
3. Дальнейшее уточнение и подтверждение происходят в чате WhatsApp.

Критерии приемки:

- заказ в первой версии не сохраняется как отдельная запись в базе;
- история отправленных заказов на сайте не нужна;
- CRM в первой версии не нужна;
- работник получает только то, что клиент отправил через WhatsApp.

## US-WK-05. Не получать недоступные позиции

История:

```text
Как работник магазина,
я хочу получать только доступные позиции,
чтобы не тратить время на товары, которые уже нельзя заказать.
```

Основной сценарий:

1. Клиент добавил товары в корзину.
2. Часть товаров стала недоступной до отправки.
3. Сайт актуализировал корзину.
4. В WhatsApp ушли только доступные позиции.

Критерии приемки:

- товары **нет в наличии** не попадают в WhatsApp-сообщение;
- недоступные вкусы не попадают в WhatsApp-сообщение;
- скрытые и удаленные товары не попадают в WhatsApp-сообщение;
- сумма товаров считается только по позициям, которые реально отправляются.
