# User Stories Spec: Admin Catalog Management v0.1

## 1. Назначение

Этот документ описывает истории владельца каталога в админке.

Главная цель владельца - управлять ассортиментом, ценами, фото, вкусами, категориями, статусами и сортировкой без разработки.

## US-AD-01. Войти в админку

История:

```text
Как владелец каталога,
я хочу войти в админку по логину и паролю,
чтобы управлять каталогом без доступа клиентов.
```

Основной сценарий:

1. Владелец открывает `/admin/login`.
2. Владелец вводит общий логин и общий пароль.
3. Владелец нажимает вход.
4. Если данные верные, открывается админка.

Критерии приемки:

- используется один общий логин и один общий пароль;
- сложной системы ролей нет;
- отдельные аккаунты работников не нужны;
- если логин или пароль неверные, показывается общая ошибка;
- ошибка не раскрывает, что именно неверно;
- клиентский каталог не показывает ссылку на админку;
- владелец может выйти из админки;
- после выхода админка не открывается без повторного входа.

## US-AD-02. Смотреть и искать товары в админке

История:

```text
Как владелец каталога,
я хочу видеть список товаров и быстро искать товар по названию,
чтобы быстро менять цену, фото, статус или другие данные.
```

Основной сценарий:

1. Владелец входит в админку.
2. Владелец открывает список товаров.
3. Владелец смотрит товары или вводит название в поиск.
4. Владелец открывает нужный товар для редактирования.

Критерии приемки:

- список товаров показывает товары, которые не удалены;
- в списке видны фото, название, категория, цена, количество штук в одной уп, статус и признак вкусов;
- поиск работает по названию товара;
- скрытые товары доступны в отдельном списке;
- черновики доступны в отдельном списке;
- удаленные товары не показываются владельцу в обычном списке.

## US-AD-03. Добавить новый товар

История:

```text
Как владелец каталога,
я хочу добавить новый товар,
чтобы он появился в клиентском каталоге с правильной ценой и фото.
```

Основной сценарий:

1. Владелец открывает добавление товара.
2. Владелец вводит название.
3. Владелец выбирает категорию.
4. Владелец указывает цену.
5. Владелец указывает количество штук в одной уп.
6. Владелец добавляет основное фото.
7. Владелец сохраняет товар.
8. Товар появляется в клиентском каталоге, если он не скрыт и не является черновиком.

Критерии приемки:

- название обязательно;
- категория обязательна для публикации;
- цена обязательна для клиентского каталога;
- основное фото обязательно для клиентского каталога;
- количество штук в одной уп обязательно для клиентского каталога;
- описания товара в первой версии нет;
- объем, тара или формат указываются в названии товара;
- если у товара нет выбора вкуса, записи во вкусах не создаются;
- новый товар по умолчанию попадает в конец **Все напитки** и в конец своей категории.

## US-AD-04. Сохранить товар как черновик

История:

```text
Как владелец каталога,
я хочу сохранить незаполненный товар как черновик,
чтобы продолжить заполнение позже и не показать сырой товар клиенту.
```

Основной сценарий:

1. Владелец начал добавлять товар.
2. У товара не хватает основного фото, цены или количества штук в одной уп.
3. Владелец выбирает действие **Сохранить как черновик**.
4. Товар сохраняется в списке черновиков.

Критерии приемки:

- система не публикует товар без обязательных данных;
- черновик виден владельцу в отдельном списке;
- черновик не виден клиенту;
- черновик не попадает в поиск клиента;
- черновик нельзя добавить в заказ;
- система не сохраняет черновик автоматически без решения владельца.

## US-AD-05. Редактировать товар

История:

```text
Как владелец каталога,
я хочу редактировать товар,
чтобы быстро менять ассортимент без помощи разработчика.
```

Основной сценарий:

1. Владелец находит товар.
2. Владелец открывает редактирование.
3. Владелец меняет нужные поля.
4. Владелец сохраняет изменения.
5. Изменения отражаются в клиентском каталоге, если товар видим клиенту.

Критерии приемки:

- можно изменить название;
- можно изменить категорию;
- можно изменить цену;
- можно изменить количество штук в одной уп;
- можно заменить основное фото;
- можно изменить статус товара;
- можно изменить вкусы товара;
- если категория изменилась, товар исчезает из старой категории;
- список старой категории смыкается без пустого места;
- после смены категории товар попадает в конец новой категории, если владелец не переставил его вручную.

## US-AD-06. Управлять вкусами товара

История:

```text
Как владелец каталога,
я хочу управлять вкусами товара,
чтобы клиент мог выбрать нужный вкус в одной карточке товара.
```

Основной сценарий:

1. Владелец открывает товар с выбором вкуса.
2. Владелец изменяет список вкусов.
3. Для вкуса владелец указывает название.
4. При необходимости владелец задает отдельную цену или фото вкуса.
5. При необходимости владелец отмечает вкус как **нет в наличии**.

Критерии приемки:

- товар с несколькими вкусами остается одним товаром;
- каждый вкус должен иметь название;
- отдельная цена вкуса нужна только если она отличается от базовой;
- если у вкуса нет отдельной цены, используется базовая цена товара;
- фото вкуса необязательно;
- если у вкуса нет отдельного фото, используется основное фото товара;
- отдельный вкус можно отметить как **нет в наличии**;
- если все вкусы недоступны, товар остается видимым клиенту, но недоступен для заказа;
- состояние "все вкусы недоступны" не хранится отдельным статусом товара.

## US-AD-07. Управлять статусом товара

История:

```text
Как владелец каталога,
я хочу менять статус товара,
чтобы клиент видел только актуальный и правильно отмеченный ассортимент.
```

Основной сценарий:

1. Владелец открывает товар.
2. Владелец выбирает нужный статус.
3. Владелец сохраняет изменения.
4. Клиентский каталог меняется по правилам статуса.

Критерии приемки:

- статус **доступен для заказа** позволяет клиенту добавить товар;
- статус **нет в наличии** оставляет товар видимым, но недоступным для заказа;
- статус **скрыт из клиентского каталога** убирает товар от клиента;
- статус **черновик** убирает товар от клиента;
- перед скрытием товара нужно подтверждение;
- скрытый товар доступен владельцу в отдельном списке;
- скрытый товар можно вернуть в клиентский каталог.

## US-AD-08. Удалить товар

История:

```text
Как владелец каталога,
я хочу удалить товар,
чтобы убрать его из админки и клиентского каталога, если он больше не нужен.
```

Основной сценарий:

1. Владелец открывает товар.
2. Владелец нажимает удаление.
3. Система просит подтвердить удаление.
4. Владелец подтверждает.
5. Товар исчезает из клиентского каталога и обычного списка админки.

Критерии приемки:

- перед удалением нужно подтверждение;
- удаленный товар не виден клиенту;
- удаленный товар не виден владельцу в обычном списке;
- отдельный список удаленных товаров в первой версии не нужен;
- если удаленный товар был в корзине клиента, он исчезает из корзины при актуализации.

## US-AD-09. Управлять категориями

История:

```text
Как владелец каталога,
я хочу управлять категориями,
чтобы структура каталога соответствовала реальному ассортименту.
```

Основной сценарий:

1. Владелец открывает раздел категорий.
2. Владелец добавляет, переименовывает, удаляет или сортирует категории.
3. Клиентский каталог показывает актуальный список категорий.

Критерии приемки:

- можно добавить категорию;
- можно переименовать категорию;
- можно удалить пустую категорию;
- категорию с товарами удалить нельзя;
- название категории должно быть уникальным;
- новая категория попадает в конец списка;
- порядок категорий меняется через перетаскивание;
- **Все напитки** не является категорией;
- **Все напитки** нельзя удалить, переименовать или переместить;
- фильтр **Все напитки** всегда показывается первым.

## US-AD-10. Настроить порядок товаров

История:

```text
Как владелец каталога,
я хочу вручную менять порядок товаров,
чтобы ходовые и важные позиции были выше для клиента.
```

Основной сценарий:

1. Владелец открывает сортировку **Все напитки** или сортировку конкретной категории.
2. Владелец перетаскивает товары в нужном порядке.
3. Владелец сохраняет порядок.
4. Клиент видит товары в заданном порядке.

Критерии приемки:

- порядок **Все напитки** редактируется отдельно;
- порядок внутри каждой категории редактируется отдельно;
- порядок **Все напитки** и порядок внутри категории могут отличаться;
- порядок меняется через перетаскивание;
- порядок не редактируется отдельным числовым полем;
- если владелец не менял порядок, новый товар остается в конце списка.

## US-AD-11. Загрузить или заменить фото

История:

```text
Как владелец каталога,
я хочу загрузить или заменить фото товара,
чтобы клиент видел товар перед заказом.
```

Основной сценарий:

1. Владелец открывает товар.
2. Владелец загружает основное фото товара.
3. При необходимости владелец загружает фото вкуса.
4. Сайт сохраняет фото и показывает его в каталоге.

Критерии приемки:

- основное фото обязательно для клиентского каталога;
- фото вкуса необязательно;
- если фото вкуса нет, клиент видит основное фото товара;
- допустимые форматы: JPG, PNG, WebP;
- файл больше лимита должен дать понятную ошибку;
- загружать и менять фото может только админка после входа;
- клиентский каталог может только читать фото.
