# Work Plan: Админка - быстрая отметка товара нет в наличии

Дата: 2026-06-27

Статус: завершен, владелец проверил и попросил сделать push

Рабочая ветка после утверждения плана: `feature/admin-product-stock-quick-action`

## 1. Цель

Добавить на карточку товара в админке быстрое действие для перевода товара в статус **Нет в наличии**, чтобы владельцу не нужно было открывать форму редактирования товара только ради смены статуса.

Главный результат:

```text
Владелец после входа в админку может прямо с карточки товара отметить товар как нет в наличии и вернуть его в наличие.
```

## 3. Scope работы

### 3.1. Быстро отметить товар как нет в наличии

Нужно:

- добавить на карточку товара в `/admin/products` действие **Нет в наличии** для товара со статусом `active`;
- перед изменением статуса показать подтверждение;
- после подтверждения перевести товар в статус `out_of_stock`;
- после успешного действия оставить товар в обычном списке `/admin/products`, потому что список показывает и `active`, и `out_of_stock`;
- обновить карточку или список так, чтобы владелец сразу увидел новый статус;
- сохранить существующее поведение клиентского каталога: товар виден клиенту, но недоступен для заказа.

### 3.2. Быстро вернуть товар в наличие

Нужно:

- добавить на карточку товара в `/admin/products` действие **В наличие** или **Вернуть в наличие** для товара со статусом `out_of_stock`;
- перед изменением статуса показать подтверждение;
- после подтверждения перевести товар в статус `active`;
- перед переводом в `active` проверить обязательные данные для публикации товара:
  - название;
  - категория;
  - цена;
  - количество штук в одной уп;
  - основное фото;
- если обязательных данных не хватает, не переводить товар в `active` и показать понятную ошибку;
- после успешного действия обновить карточку или список так, чтобы владелец сразу увидел новый статус.

### 3.3. Серверная защита и API

Нужно:

- выполнять изменение статуса только через защищенный серверный API после проверки админской сессии;
- не отправлять `SUPABASE_SERVICE_ROLE_KEY` или другие секреты в браузер;
- корректно обработать:
  - потерю админской сессии;
  - товар не найден;
  - товар удален;
  - попытку вернуть в наличие товар без обязательных данных;
  - повторное действие, если товар уже находится в нужном статусе.

Допустимый технический вариант:

```text
POST /api/admin/products/{id}/mark-out-of-stock
POST /api/admin/products/{id}/mark-active
```

Или другой близкий вариант, если он лучше ложится на существующий код быстрых действий.

### 3.4. Интерфейс

Нужно:

- встроить новые действия в существующий блок быстрых действий карточки товара рядом с **Скрыть** и **Удалить**;
- использовать русские тексты кнопок, подтверждений, ошибок и состояний загрузки;
- сохранить адаптивность карточек на телефоне и desktop;
- не добавлять ссылку на админку в клиентский каталог;
- не менять клиентский дизайн каталога, корзины, оформления заказа и WhatsApp-сообщения.

## 4. Что не входит в этот план

В этот work plan не входит:

- изменение формы редактирования товара;
- управление вкусами товара;
- отметка отдельных вкусов как **Нет в наличии**;
- скрытие товара;
- удаление товара;
- восстановление удаленного товара;
- управление категориями;
- drag-and-drop сортировка товаров или категорий;
- изменение клиентского интерфейса каталога, корзины, оформления заказа и WhatsApp-сообщения;
- деплой на Vercel.

## 5. Проверки

После реализации нужно выполнить:

```text
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run build
git diff --check
git status --short --branch
```

Дополнительно вручную проверить:

- `/admin/products` без входа переводит на `/admin/login`;
- у товара со статусом `active` на карточке есть действие **Нет в наличии**;
- подтверждение перед переводом в **Нет в наличии** появляется;
- после подтверждения товар получает статус `out_of_stock` и остается в `/admin/products`;
- клиентский каталог показывает такой товар, но не дает добавить его в заказ;
- у товара со статусом `out_of_stock` на карточке есть действие **В наличие** или **Вернуть в наличие**;
- подтверждение перед возвратом в наличие появляется;
- после подтверждения товар получает статус `active`;
- если обязательных данных для `active` не хватает, владелец видит понятную ошибку;
- кнопки **Скрыть**, **Удалить**, **Редактировать** и выход из админки продолжают работать;
- в клиентском каталоге не появилась ссылка на админку;
- секреты Supabase не попали в клиентский код.

## 6. Критерии готовности

План считается выполненным, когда:

- владелец может быстро отметить активный товар как **Нет в наличии** с карточки товара;
- владелец может быстро вернуть товар из **Нет в наличии** в **Доступен** с карточки товара;
- все новые действия закрыты проверкой админской сессии;
- сервер не переводит товар в `active`, если не хватает обязательных данных;
- клиентский каталог, корзина и WhatsApp продолжают работать по существующим правилам доступности товара;
- интерфейс работает на телефоне и desktop;
- проверки завершены успешно;
- результат показан владельцу для ручной проверки.
