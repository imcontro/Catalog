# Work Plan: Админка - загрузка и замена основного фото товара

Дата: 2026-06-26

Статус: завершен, отправлен в GitHub

Рабочая ветка после утверждения плана: `feature/admin-product-main-image`

## 1. Цель

Добавить в админку первый рабочий сценарий управления основным фото товара: владелец открывает форму товара, загружает новое основное фото или заменяет текущее, сохраняет товар, и фото используется в админке и клиентском каталоге.

Главный результат:

```text
Владелец после входа в админку может загрузить или заменить основное фото товара без разработки.
```

## 3. Scope работы

### 3.1. Загрузка изображения

Нужно:

- добавить защищенный серверный API:

```text
POST /api/admin/images
```

- принимать файл изображения через форму админки;
- разрешить только форматы:
  - JPG;
  - PNG;
  - WebP;
- ограничить размер файла до 5 МБ;
- показывать понятную ошибку, если файл не выбран, формат не поддерживается или файл больше лимита;
- не использовать исходное имя файла как путь в Storage;
- загружать файл в Supabase Storage bucket `product-images`;
- создавать запись в таблице `images`;
- возвращать `imageId` и публичную ссылку на фото.

### 3.2. Привязка основного фото к товару

Нужно:

- расширить сохранение товара так, чтобы форма могла передать `mainImageId`;
- при создании или редактировании товара записывать выбранное фото в `products.main_image_id`;
- сохранить существующее правило: товар нельзя поставить в статус `active` или `out_of_stock`, если нет основного фото и других обязательных данных;
- после успешной загрузки показывать новое фото в форме до сохранения товара;
- после успешного сохранения показывать обновленное фото в списках админки и в клиентском каталоге по уже существующим правилам чтения данных.

### 3.3. Интерфейс формы товара

Нужно:

- в существующей форме товара заменить статичный блок фото на рабочий блок основного фото;
- если фото уже есть, показывать текущее основное фото;
- если фото нет, показывать состояние **Фото не добавлено**;
- добавить элемент выбора файла;
- добавить действие загрузки или замены фото с русским текстом;
- показывать состояние загрузки;
- показывать ошибку загрузки официальным понятным текстом;
- не отправлять секреты Supabase в браузер;
- сохранить адаптивность формы на телефоне и desktop.

### 3.4. Хранение и обработка

Нужно:

- использовать Supabase Storage через серверную часть приложения;
- использовать `SUPABASE_SERVICE_ROLE_KEY` только на сервере;
- записывать в `images`:
  - `storage_path`;
  - `public_url`;
  - `original_name`;
  - `mime_type`;
  - `size_bytes`;
  - `width` и `height`, если эти данные можно получить без усложнения реализации;
- если обработка изображения или получение размеров потребуют отдельной тяжелой зависимости, в этом plan можно сохранить оригинал без ресайза, потому что technical spec допускает начать с сохранения оригинала при ограничении размера файла.

## 4. Что не входит в этот план

В этот work plan не входит:

- загрузка или замена фото вкуса;
- управление вкусами товара;
- изменение `has_flavor_choice`;
- отдельные цены вкусов;
- отметка отдельного вкуса как **нет в наличии**;
- удаление старого фото из Storage при замене;
- очистка неиспользуемых фото;
- кадрирование, ручное редактирование или поворот фото в интерфейсе;
- HEIC и другие форматы кроме JPG, PNG и WebP;
- drag-and-drop сортировка;
- управление категориями;
- удаление товара;
- изменение клиентского сценария корзины, оформления заказа и WhatsApp;
- деплой на Vercel.

## 5. Проверки

После реализации нужно выполнить:

```text
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run build
git diff --check
git status --short --branch
```

Дополнительно вручную проверить:

- `/admin/products/new` без входа переводит на `/admin/login`;
- `/admin/products/[id]/edit` без входа переводит на `/admin/login`;
- после входа можно открыть форму нового товара;
- можно выбрать допустимый JPG, PNG или WebP до 5 МБ;
- после загрузки фото оно показывается в форме;
- новый товар с фото можно сохранить;
- существующий товар можно открыть и заменить основное фото;
- после сохранения новое фото видно в списке `/admin/products`;
- черновик с фото виден в `/admin/drafts`;
- товар нельзя опубликовать без основного фото;
- файл больше 5 МБ дает понятную ошибку;
- неподдерживаемый формат дает понятную ошибку;
- клиентский каталог продолжает читать фото по существующим правилам;
- в клиентском каталоге не появилась ссылка на админку;
- секреты Supabase не попали в клиентский код.

## 6. Критерии готовности

План считается выполненным, когда:

- защищенный API загрузки фото работает только для администратора;
- фото сохраняется в Supabase Storage bucket `product-images`;
- запись о фото создается в таблице `images`;
- `products.main_image_id` обновляется при сохранении товара;
- форма создания и редактирования товара показывает текущее или новое основное фото;
- правило обязательного основного фото для публикации сохранено;
- ошибки загрузки понятны владельцу и написаны на русском языке;
- интерфейс работает на телефоне и desktop;
- проверки завершены успешно;
- результат показан владельцу для ручной проверки.
