# Work Plan: цена за штуку и desktop-прокрутка категорий

## 1. Статус

Утвержден владельцем для реализации.

После утверждения плана работа должна идти в отдельной ветке:

```text
feature/client-catalog-unit-price-and-desktop-categories
```

## 3. Цель

Сделать клиентский каталог удобнее перед следующим крупным этапом:

- на компьютере клиент должен иметь возможность добраться до всех категорий;
- в карточке товара клиент должен видеть не только цену за упаковку, но и примерную цену за одну штуку.

## 4. Scope

В scope входит:

- исправить desktop-поведение горизонтального списка категорий в клиентском каталоге;
- сохранить текущее удобное поведение категорий на телефоне;
- добавить на карточку товара примерную цену за штуку;
- считать цену за штуку от текущей эффективной цены карточки и количества штук в упаковке;
- при выборе вкуса с отдельной ценой пересчитывать цену за штуку;
- показывать цену за штуку в формате `≈ 27,5 ₽/шт`;
- округлять дробную цену за штуку до одного знака после запятой;
- не показывать лишний ноль после запятой;
- проверить, что карточки остаются читаемыми на телефоне и компьютере.

Не входит в scope:

- изменение схемы базы данных;
- миграции;
- изменение импорта старого каталога;
- изменение админки;
- изменение корзины и WhatsApp-сообщения;
- изменение цен в Supabase;
- деплой на Vercel;
- подключение боевого Supabase;
- новый дизайн всего каталога.

## 5. Функциональные требования

### 5.1. Категории на компьютере

Список категорий в клиентском каталоге должен оставаться горизонтальным быстрым фильтром.

На desktop-экране клиент должен иметь возможность открыть любую категорию, даже если все категории не помещаются в видимую ширину.

Допустимые решения:

- горизонтальная прокрутка колесом мыши, тачпадом или полосой прокрутки;
- кнопки прокрутки влево и вправо;
- другое компактное решение, которое не ломает мобильную версию.

Решение не должно превращать категории в большой вертикальный список на первом экране.

### 5.2. Цена за штуку

Карточка товара должна показывать:

- цену за упаковку как основную цену;
- количество штук в упаковке в формате `{число} шт в уп`;
- примерную цену за штуку в формате `≈ 27,5 ₽/шт`.

Формула:

```text
цена за штуку = эффективная цена карточки / количество штук в упаковке
```

Если товар без выбора вкуса, эффективная цена равна базовой цене товара.

Если товар с выбором вкуса:

- до выбора вкуса используется цена первого вкуса по текущим правилам карточки;
- после выбора вкуса используется эффективная цена выбранного вкуса;
- если у вкуса нет отдельной цены, используется базовая цена товара.

## 6. Технический план

1. Перед разработкой перейти на `main`.
2. Обновить `main` через `git pull --ff-only origin main`, если нет чужих незавершенных изменений.
3. Создать ветку `feature/client-catalog-unit-price-and-desktop-categories`.
4. Найти компоненты клиентского каталога, карточки товара и списка категорий.
5. Добавить helper для вычисления и форматирования цены за штуку или использовать существующий форматтер цены, если он уже подходит.
6. Добавить отображение цены за штуку в карточку товара рядом с ценой/упаковкой по design spec.
7. Исправить desktop-прокрутку категорий.
8. Проверить mobile и desktop-версию локально.
9. Выполнить проверки.

## 7. Проверки

Обязательные команды:

```text
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run build
git diff --check
```

Ручные проверки:

- на desktop-ширине можно добраться до всех категорий;
- на телефоне категории работают как раньше;
- цена за упаковку осталась заметной;
- цена за штуку отображается в формате `≈ 27,5 ₽/шт`;
- при выборе вкуса с другой ценой цена за штуку пересчитывается;
- товары без выбора вкуса показывают цену за штуку от базовой цены;
- карточки не ломаются визуально на телефоне и компьютере;
- добавление в корзину работает как раньше.

## 8. Критерии готовности

- Все категории доступны на компьютере.
- Мобильное поведение категорий не ухудшилось.
- На карточках товаров показана примерная цена за штуку.
- Цена за штуку считается от актуальной цены карточки.
- Корзина, оформление заказа и WhatsApp не изменены.
- Проверки проходят.
- Владелец проверил результат локально.
