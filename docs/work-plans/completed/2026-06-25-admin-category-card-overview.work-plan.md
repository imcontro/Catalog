# Work Plan: Админка - карточки товаров по категориям

Дата: 2026-06-25

Статус: утвержден владельцем для реализации

Рабочая ветка после утверждения плана: `feature/admin-category-card-overview`

## 1. Цель

Сделать список товаров в админке более удобным для визуальной работы с каталогом: показывать товары карточками с крупным фото и переключением по категориям, близко к логике основного клиентского каталога, но в спокойном рабочем стиле админки.

Главный результат:

```text
Владелец после входа в админку может смотреть товары карточками, быстро переключаться между категориями, видеть фото и основные данные товара перед следующим этапом редактирования.
```

Работа опирается на:

- `docs/features/06-admin-products.feature-spec.md`;
- `docs/features/01-client-catalog.feature-spec.md`;
- `docs/features/07-empty-and-error-states.feature-spec.md`;

Важное дизайн-ограничение:

- админка не должна буквально копировать клиентскую витрину;
- карточки в этом plan нужны как рабочий админский обзор с фото, статусами и служебными данными;
- клиентские действия корзины, выбора вкуса для заказа и оформления заказа в админку не переносятся.

## 3. Scope работ

### 3.1. Карточный вид `/admin/products`

Нужно:

- обновить защищенную страницу `/admin/products`;
- оставить серверную проверку админской сессии;
- заменить текущий строковый список товаров на карточный обзор;
- карточка товара должна показывать:
  - фото;
  - название;
  - категорию;
  - цену;
  - количество штук в одной уп;
  - статус;
  - признак наличия вкусов;
- обычный список продолжает показывать только товары, которые:
  - не удалены;
  - имеют статус `active` или `out_of_stock`;
- скрытые товары и черновики не попадают в обычный список;
- удаленные товары не показываются.

### 3.2. Категории в админском списке

Нужно:

- добавить на `/admin/products` переключатели категорий по логике клиентского каталога;
- первым переключателем показать **Все напитки**;
- после **Все напитки** показать реальные категории в порядке `categories.sort_order`;
- при выборе **Все напитки** показывать товары в порядке `products.all_drinks_sort_order`;
- при выборе категории показывать товары этой категории в порядке `products.category_sort_order`;
- не создавать категорию **Все напитки** в базе;
- если в выбранной категории нет товаров для обычного списка, показать понятное пустое состояние.

### 3.3. Поиск в карточном виде

Нужно:

- сохранить поиск по названию товара на `/admin/products`;
- выполнять поиск на сервере по параметру запроса;
- сохранять введенный запрос в поле поиска;
- поиск должен работать вместе с выбранным режимом:
  - в **Все напитки** искать по обычному списку товаров;
  - в выбранной категории искать по товарам этой категории;
- при пустом результате показать понятное состояние.

### 3.4. Черновики и скрытые товары

Нужно:

- привести `/admin/drafts` и `/admin/hidden` к тому же карточному отображению товара;
- для черновиков показывать товары со статусом `draft`, которые не удалены;
- для скрытых показывать товары со статусом `hidden`, которые не удалены;
- для товаров без категории показывать текст **Категория не выбрана**;
- сохранить понятные пустые состояния.

### 3.5. Навигация админки

Нужно:

- оставить верхние переходы между разделами **Товары**, **Черновики**, **Скрытые**;
- оставить кнопку выхода из админки;
- не добавлять видимые ссылки на админку в клиентский каталог.

### 3.6. Подготовка к следующему этапу редактирования

Нужно:

- сделать структуру компонента карточки такой, чтобы в следующем plan можно было добавить действие **Редактировать** без полной переделки списка;
- не добавлять неработающие кнопки редактирования;
- не создавать маршруты редактирования, если они не реализуют сохранение данных в рамках этого plan.

## 4. Что не входит в этот план

В этот work plan не входит:

- добавление товара;
- редактирование товара;
- создание страницы редактирования товара;
- изменение цены;
- изменение количества штук в одной уп;
- изменение статуса товара;
- скрытие товара;
- возврат скрытого товара;
- удаление товара;
- управление вкусами;
- загрузка или замена фото;
- управление категориями;
- сортировка категорий;
- drag-and-drop сортировка товаров;
- изменение клиентского каталога, корзины, оформления заказа и WhatsApp-сообщения;
- создание новых таблиц или миграций;
- деплой на Vercel.

## 5. Проверки

После реализации нужно выполнить:

```text
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run build
git diff --check
git status --short --branch
```

Дополнительно вручную проверить:

- `/admin/products` без входа переводит на `/admin/login`;
- после входа `/admin/products` открывается;
- **Все напитки** показывает обычные товары карточками;
- категории показываются после **Все напитки**;
- выбор категории меняет набор карточек;
- порядок в **Все напитки** соответствует текущему порядку `all_drinks_sort_order`;
- порядок внутри категории соответствует `category_sort_order`;
- скрытые товары не попадают в обычный список;
- черновики не попадают в обычный список;
- удаленные товары не показываются;
- поиск по названию работает в **Все напитки**;
- поиск по названию работает внутри выбранной категории;
- поиск без результата показывает понятное состояние;
- `/admin/drafts` показывает черновики карточками или пустое состояние;
- `/admin/hidden` показывает скрытые товары карточками или пустое состояние;
- у карточки видны фото, название, категория, цена, количество штук в одной уп, статус и признак вкусов;
- кнопка выхода из админки продолжает работать;
- в клиентском каталоге не появилась ссылка на админку.

## 6. Критерии готовности

План считается выполненным, когда:

- владелец после входа видит товары в админке карточками;
- карточки удобны для визуальной проверки фото и основных данных;
- категории работают как переключатели админского списка;
- поиск по названию продолжает работать на серверных данных;
- обычный список, черновики и скрытые соблюдают правила видимости из specs;
- все новые и обновленные тексты интерфейса написаны на русском языке;
- проверки завершены успешно;
- результат показан владельцу для ручной проверки.

## 7. Git-порядок после утверждения

После утверждения владельцем:

1. Убедиться, что локальная ветка `main` актуальна.
2. Создать ветку `feature/admin-category-card-overview` от актуальной `main`.
3. Выполнить только scope этого work plan.
4. Запустить проверки.
5. Показать результат владельцу для ручной проверки.
6. Commit и push делать только после отдельной просьбы владельца.
