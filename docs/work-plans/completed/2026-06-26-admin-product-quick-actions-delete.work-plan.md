# Work Plan: Админка - быстрые действия и удаление товара

Дата: 2026-06-26

Статус: завершен, отправлен в GitHub

Рабочая ветка после утверждения плана: `feature/admin-product-quick-actions-delete`

## 1. Цель

Добавить в админку быстрые действия для управления состоянием товара с карточек: скрыть товар, вернуть скрытый товар в каталог и удалить товар с подтверждением.

Главный результат:

```text
Владелец после входа в админку может быстро скрыть, вернуть или удалить товар без открытия формы редактирования.
```

## 3. Scope работы

### 3.1. Быстрое скрытие товара

Нужно:

- добавить на карточку товара в `/admin/products` действие **Скрыть**;
- перед скрытием показать подтверждение;
- после подтверждения перевести товар в статус `hidden`;
- убрать товар из обычного списка товаров;
- показать товар в `/admin/hidden`;
- не показывать скрытый товар в клиентском каталоге;
- если скрытый товар был в корзине клиента, сохранить существующее правило актуализации: позиция исчезает из корзины при следующей актуализации.

### 3.2. Возврат скрытого товара

Нужно:

- добавить на карточку товара в `/admin/hidden` действие **Вернуть в каталог**;
- возвращать скрытый товар в статус `active`, если заполнены обязательные данные для клиентского каталога:
  - название;
  - категория;
  - цена;
  - количество штук в одной уп;
  - основное фото;
- если обязательных данных не хватает, не публиковать товар и показать понятную ошибку;
- после успешного возврата убрать товар из `/admin/hidden` и показать в обычном списке `/admin/products`;
- не менять сортировку товара, кроме уже существующих правил сохранения порядка.

### 3.3. Удаление товара

Нужно:

- добавить действие **Удалить** на карточки товаров в:
  - `/admin/products`;
  - `/admin/drafts`;
  - `/admin/hidden`;
- перед удалением показать подтверждение;
- добавить или использовать защищенный серверный API:

```text
DELETE /api/admin/products/{id}
```

- выполнять мягкое удаление через `products.deleted_at`;
- после удаления товар должен исчезнуть из обычного списка, черновиков и скрытых товаров;
- удаленный товар не должен показываться клиенту;
- отдельный список удаленных товаров не создавать;
- не удалять фото из Supabase Storage при удалении товара.

### 3.4. Серверная защита и проверки

Нужно:

- все новые действия выполнять только после проверки админской сессии;
- не отправлять `SUPABASE_SERVICE_ROLE_KEY` или другие секреты в браузер;
- возвращать официальные русские сообщения об ошибках;
- корректно обрабатывать случаи:
  - товар не найден;
  - товар уже удален;
  - сессия администратора потеряна;
  - публикация скрытого товара невозможна из-за нехватки обязательных данных.

### 3.5. Интерфейс

Нужно:

- добавить действия в существующий карточный интерфейс админки без изменения общей структуры разделов;
- использовать русские тексты кнопок, подтверждений, ошибок и успешных состояний;
- сохранить адаптивность на телефоне и desktop;
- после успешного действия обновлять список так, чтобы владелец сразу видел результат;
- не добавлять ссылку на админку в клиентский каталог.

## 4. Что не входит в этот план

В этот work plan не входит:

- управление вкусами товара;
- изменение `has_flavor_choice`;
- загрузка или замена фото вкуса;
- загрузка или замена основного фото;
- удаление старых фото из Storage;
- очистка неиспользуемых фото;
- управление категориями;
- удаление категорий;
- drag-and-drop сортировка товаров или категорий;
- отдельная страница удаленных товаров;
- восстановление удаленного товара;
- изменение клиентского интерфейса каталога, корзины, оформления заказа и WhatsApp-сообщения, кроме проверки уже существующей актуализации скрытых и удаленных товаров;
- деплой на Vercel.

Ручная проверка владельцем по UI выполняется после открытия Pull Request.

## 6. Критерии готовности

План считается выполненным, когда:

- владелец может скрыть товар с подтверждением;
- владелец может вернуть скрытый товар в каталог при наличии обязательных данных;
- владелец видит понятную ошибку, если скрытый товар нельзя вернуть из-за нехватки обязательных данных;
- владелец может удалить товар с подтверждением;
- удаление работает мягко через `deleted_at`;
- скрытые и удаленные товары не попадают в клиентский каталог;
- удаленные товары не показываются в списках админки;
- фото товара не удаляются из Storage при удалении товара;
- все новые API и действия закрыты проверкой админской сессии;
- интерфейс работает на телефоне и desktop;
- проверки завершены успешно;
- результат показан владельцу для ручной проверки.
