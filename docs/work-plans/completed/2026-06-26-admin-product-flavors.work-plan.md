# Work Plan: Админка - управление вкусами товара

Дата: 2026-06-26

Статус: завершен, владелец проверил и попросил сделать push

Рабочая ветка после утверждения плана: `feature/admin-product-flavors`

## 1. Цель

Добавить в форму создания и редактирования товара управление вкусами: владелец может включить выбор вкуса, добавить и изменить вкусы, задать отдельную цену, загрузить фото вкуса и отметить отдельный вкус как **нет в наличии**.

Главный результат:

```text
Владелец после входа в админку может управлять вкусами товара без разработки.
```

## 3. Scope работы

### 3.1. Чтение вкусов в форме товара

Нужно:

- расширить загрузку товара для `/admin/products/[id]/edit`, чтобы форма получала список вкусов товара;
- показывать вкусы в порядке `product_flavors.sort_order`;
- для каждого вкуса показывать:
  - название;
  - отдельную цену, если она есть;
  - фото вкуса, если оно есть;
  - отметку **Нет в наличии**;
  - состояние **Используется основное фото**, если отдельного фото нет;
- если у товара `has_flavor_choice = false`, показывать состояние **Без выбора вкуса** и не требовать записи вкусов.

### 3.2. Включение и выключение выбора вкуса

Нужно:

- добавить в форму товара управление признаком `has_flavor_choice`;
- если выбор вкуса включен, владелец должен иметь возможность добавить хотя бы один вкус;
- если владелец пытается сохранить товар с включенным выбором вкуса без вкусов, показать понятную ошибку;
- если выбор вкуса выключен, товар сохраняется без записей во вкусах для клиентского сценария;
- при выключении выбора вкуса существующие вкусы можно удалить или очистить только после явного действия владельца в форме сохранения.

### 3.3. Добавление и редактирование вкусов

Нужно:

- дать владельцу добавить новый вкус;
- дать владельцу изменить название вкуса;
- дать владельцу удалить вкус из списка товара;
- не разрешать сохранить вкус без названия;
- сохранять порядок вкусов последовательными значениями `sort_order`;
- новые вкусы добавлять в конец списка вкусов товара;
- не создавать отдельный системный вкус для товара без выбора вкуса.

### 3.4. Отдельная цена вкуса

Нужно:

- дать владельцу указать отдельную цену вкуса в рублях;
- разрешить оставить цену вкуса пустой, тогда в клиентском каталоге используется базовая цена товара;
- проверять, что отдельная цена вкуса является положительным целым числом;
- после сохранения клиентский каталог, корзина и WhatsApp используют актуальную эффективную цену по существующим правилам.

### 3.5. Фото вкуса

Нужно:

- использовать существующий защищенный API `POST /api/admin/images` для загрузки фото вкуса;
- дать владельцу загрузить или заменить фото отдельного вкуса;
- разрешить оставить вкус без отдельного фото;
- если фото вкуса нет, клиентский каталог и корзина используют основное фото товара;
- показывать понятную ошибку загрузки фото вкуса;
- не удалять старые фото из Supabase Storage при замене фото вкуса.

### 3.6. Наличие вкуса

Нужно:

- дать владельцу отметить отдельный вкус как **Нет в наличии**;
- дать владельцу снять эту отметку;
- сохранить значение в `product_flavors.is_out_of_stock`;
- если все вкусы товара отмечены как **Нет в наличии**, не менять основной статус товара, потому что это вычисляемое состояние;
- клиентский каталог должен продолжать показывать товар, но недоступность всех вкусов определяется по уже существующим правилам.

### 3.7. Серверная защита и проверки

Нужно:

- все изменения вкусов сохранять только через защищенные серверные API после проверки админской сессии;
- не отправлять `SUPABASE_SERVICE_ROLE_KEY` или другие секреты в браузер;
- сохранять изменения вкусов атомарно вместе с сохранением товара, чтобы форма не оставляла частично обновленный список вкусов;
- корректно обрабатывать:
  - товар не найден;
  - товар удален;
  - пустое название вкуса;
  - некорректную цену вкуса;
  - потерю админской сессии;
  - попытку включить выбор вкуса без вкусов.

### 3.8. Интерфейс

Нужно:

- встроить управление вкусами в существующую форму товара без создания отдельного раздела админки;
- использовать русские тексты кнопок, подписей, ошибок и состояний;
- сохранить адаптивность формы на телефоне и desktop;
- после успешного сохранения вернуть владельца в правильный список по текущему статусу товара;
- не добавлять ссылку на админку в клиентский каталог.

## 4. Что не входит в этот план

В этот work plan не входит:

- управление категориями;
- добавление, переименование или удаление категорий;
- drag-and-drop сортировка категорий;
- drag-and-drop сортировка товаров в **Все напитки**;
- drag-and-drop сортировка товаров внутри категории;
- отдельная drag-and-drop сортировка вкусов;
- восстановление удаленных товаров;
- удаление старых фото из Supabase Storage;
- очистка неиспользуемых фото;
- изменение дизайна клиентского каталога, корзины, оформления заказа и WhatsApp-сообщения;
- деплой на Vercel.

- кнопка выхода из админки продолжает работать;
- в клиентском каталоге не появилась ссылка на админку;
- секреты Supabase не попали в клиентский код.

## 6. Критерии готовности

План считается выполненным, когда:

- владелец может включить и выключить выбор вкуса у товара;
- владелец может добавлять, изменять и удалять вкусы товара;
- сервер не сохраняет вкус без названия;
- сервер не сохраняет выбор вкуса без хотя бы одного вкуса;
- отдельная цена вкуса сохраняется и используется клиентским каталогом;
- фото вкуса можно загрузить, заменить или оставить пустым;
- вкус можно отметить как **Нет в наличии**;
- все новые API и действия закрыты проверкой админской сессии;
- изменения вкусов не ломают клиентский каталог, корзину и WhatsApp;
- интерфейс работает на телефоне и desktop;
- проверки завершены успешно;
- результат показан владельцу для ручной проверки.
