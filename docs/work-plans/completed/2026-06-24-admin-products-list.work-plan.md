# Work Plan: Админка - список товаров и поиск

Дата: 2026-06-24

Статус: утвержден владельцем для реализации

Рабочая ветка после утверждения плана: `feature/admin-products-list`

## 1. Цель

Сделать первый рабочий раздел управления каталогом в админке: защищенный список товаров, поиск по названию, отдельные списки скрытых товаров и черновиков.

Главный результат:

```text
Владелец после входа в админку видит товары из Supabase, может найти товар по названию и отдельно открыть скрытые товары или черновики.
```

## 3. Scope работ

### 3.1. Навигация админки

Нужно:

- обновить закрытую страницу `/admin`;
- оставить проверку админской сессии на сервере;
- показать владельцу понятный вход в разделы:
  - **Товары**;
  - **Черновики**;
  - **Скрытые**;
- оставить кнопку выхода из админки.

### 3.2. Обычный список товаров

Нужно:

- добавить защищенную страницу `/admin/products`;
- показывать только товары, которые:
  - не удалены;
  - имеют статус `active` или `out_of_stock`;
- не показывать в обычном списке скрытые товары и черновики;
- для каждого товара показать:
  - фото;
  - название;
  - категорию;
  - цену;
  - количество штук в одной уп;
  - статус;
  - признак наличия вкусов;
- сортировать товары по текущему порядку **Все напитки**;
- не показывать удаленные товары.

### 3.3. Поиск товаров

Нужно:

- добавить поиск по названию товара в `/admin/products`;
- выполнять поиск на сервере по параметру запроса;
- сохранять введенный запрос в поле поиска;
- при пустом результате показать понятное состояние;
- не искать по категориям, цене, вкусу или статусу в рамках этого plan.

### 3.4. Черновики

Нужно:

- добавить защищенную страницу `/admin/drafts`;
- показывать товары со статусом `draft`, которые не удалены;
- показать те же основные поля товара, что и в обычном списке;
- показать понятное пустое состояние, если черновиков нет.

### 3.5. Скрытые товары

Нужно:

- добавить защищенную страницу `/admin/hidden`;
- показывать товары со статусом `hidden`, которые не удалены;
- показать те же основные поля товара, что и в обычном списке;
- показать понятное пустое состояние, если скрытых товаров нет.

### 3.6. Серверная проверка доступа

Нужно:

- использовать существующую проверку админской сессии;
- закрыть `/admin/products`, `/admin/drafts` и `/admin/hidden` от открытия без входа;
- не добавлять видимые ссылки на админку в клиентский каталог;
- не отправлять секреты в браузер.

## 4. Что не входит в этот план

В этот work plan не входит:

- добавление товара;
- редактирование товара;
- изменение цены;
- изменение количества штук в одной уп;
- изменение статуса товара;
- скрытие товара;
- возврат скрытого товара;
- удаление товара;
- управление вкусами;
- загрузка или замена фото;
- управление категориями;
- сортировка категорий;
- сортировка товаров в **Все напитки**;
- сортировка товаров внутри категории;
- drag-and-drop;
- создание новых таблиц или миграций;
- изменение клиентского каталога, корзины, оформления заказа и WhatsApp-сообщения;
- деплой на Vercel.

## 5. Проверки

После реализации нужно выполнить:

```text
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run build
git diff --check
git status --short --branch
```

Дополнительно вручную проверить:

- `/admin/products` без входа переводит на `/admin/login`;
- после входа `/admin/products` открывается;
- обычный список показывает активные товары и товары **нет в наличии**;
- скрытые товары не попадают в обычный список;
- черновики не попадают в обычный список;
- удаленные товары не показываются;
- в строке товара видны фото, название, категория, цена, количество штук в одной уп, статус и признак вкусов;
- поиск по названию работает;
- поиск без результата показывает понятное состояние;
- `/admin/drafts` показывает черновики или пустое состояние;
- `/admin/hidden` показывает скрытые товары или пустое состояние;
- кнопка выхода из админки продолжает работать;
- в клиентском каталоге не появилась ссылка на админку.

## 6. Критерии готовности

План считается выполненным, когда:

- владелец после входа может открыть список товаров в админке;
- обычный список соответствует правилам видимости из technical spec;
- поиск по названию работает на серверных данных;
- скрытые товары и черновики открываются отдельными защищенными страницами;
- все новые админские страницы проверяют сессию на сервере;
- интерфейс, ошибки и пустые состояния написаны на русском языке;
- проверки завершены успешно;
- результат показан владельцу для ручной проверки.

## 7. Git-порядок после утверждения

После утверждения владельцем:

1. Перейти на `main`.
2. Обновить `main` через `git pull --ff-only origin main`.
3. Создать ветку `feature/admin-products-list`.
4. Выполнить только scope этого work plan.
5. Запустить проверки.
6. Показать результат владельцу для ручной проверки.
7. Commit и push делать только после отдельной просьбы владельца.
