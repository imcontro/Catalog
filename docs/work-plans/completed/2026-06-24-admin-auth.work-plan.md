# Work Plan: Админка - вход

Дата: 2026-06-24

Статус: завершен, владелец попросил сделать push

Рабочая ветка после утверждения плана: `feature/admin-auth`

## 1. Цель

Сделать первый закрытый слой админки: вход владельца по общему логину и паролю, серверную сессию и защиту админских страниц от открытия без входа.

Главный результат:

```text
Владелец может войти в админку, выйти из нее, а закрытые админские страницы не открываются без действующей сессии.
```

## 3. Scope работ

### 3.1. Переменные окружения

Нужно:

- использовать `ADMIN_LOGIN` для общего логина администратора;
- использовать `ADMIN_PASSWORD_HASH` для хеша пароля;
- не хранить пароль открытым текстом в репозитории;
- обновить `.env.example` без реальных секретов, если нужных переменных там еще нет.

### 3.2. Страница входа

Нужно:

- привести `/admin/login` к рабочей форме входа;
- показать поля логина и пароля;
- показать кнопку входа;
- обработать пустой логин;
- обработать пустой пароль;
- при неверных данных показать общую ошибку без уточнения, что именно неверно;
- после успешного входа перевести владельца в `/admin`.

### 3.3. API входа

Нужно:

- добавить или доработать `POST /api/admin/login`;
- сравнивать введенный логин с `ADMIN_LOGIN`;
- сравнивать введенный пароль с `ADMIN_PASSWORD_HASH`;
- ограничить размер полей логина и пароля;
- при успешном входе создать серверную сессию;
- при ошибке не создавать сессию и вернуть общую ошибку.

### 3.4. Сессия администратора

Нужно:

- хранить сессию в `httpOnly` cookie;
- включать `secure` на продакшене;
- использовать `sameSite`;
- задать ограниченный срок жизни cookie;
- хранить в таблице `admin_sessions` хеш токена сессии, а не сам токен;
- проверять сессию на сервере.

### 3.5. Защита админских страниц

Нужно:

- защитить `/admin`;
- подготовить общий серверный helper проверки админской сессии для будущих админских страниц и API;
- если владелец открывает закрытую админскую страницу без сессии, отправлять его на `/admin/login`;
- не показывать ссылку на админку в клиентском каталоге.

### 3.6. Выход

Нужно:

- добавить `POST /api/admin/logout`;
- добавить кнопку выхода в закрытой админке;
- при выходе помечать текущую сессию как закрытую;
- удалять cookie;
- возвращать владельца на `/admin/login`;
- не давать кнопке "Назад" открыть рабочую админку без новой проверки сессии.

## 4. Что не входит в этот план

В этот work plan не входит:

- управление товарами;
- список товаров в админке;
- добавление, редактирование, скрытие и удаление товаров;
- управление фото;
- управление вкусами;
- управление категориями;
- ручная сортировка товаров;

- регистрация новых администраторов;

## 5. Проверки

После реализации нужно выполнить:

```text
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run build
git diff --check
git status --short --branch
```

Дополнительно вручную проверить:

- `/admin/login` открывается без входа;
- пустой логин показывает понятную ошибку;
- пустой пароль показывает понятную ошибку;
- неверный логин или пароль показывает общую ошибку;
- правильные данные открывают `/admin`;
- `/admin` без сессии переводит на `/admin/login`;
- после выхода `/admin` снова не открывается без входа;
- кнопка "Назад" после выхода не открывает рабочую админку;
- cookie сессии недоступна из браузерного JavaScript;
- в клиентском каталоге нет видимой ссылки или кнопки перехода в админку;
- реальные значения `ADMIN_LOGIN` и `ADMIN_PASSWORD_HASH` не попали в Git.

## 6. Критерии готовности

План считается выполненным, когда:

- вход в админку работает по одному общему логину и паролю;
- пароль не хранится открытым текстом;
- сессия создается на сервере и хранится через защищенную cookie;
- закрытая админская страница не открывается без действующей сессии;
- выход из админки закрывает текущую сессию;
- интерфейс, ошибки и состояния написаны на русском языке;
- проверки завершены успешно;
- результат показан владельцу для ручной проверки.
