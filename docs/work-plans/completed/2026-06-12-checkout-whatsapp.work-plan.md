# Work Plan: Оформление заказа и WhatsApp

Дата: 2026-06-12

Статус: completed

Рабочая ветка после утверждения плана: `feature/checkout-whatsapp`

## 1. Цель

Завершить клиентский путь заказа после уже реализованной корзины.

Главный результат этого плана:

```text
Клиент открывает оформление заказа, указывает адрес, выбирает способ оплаты и отправляет в WhatsApp понятное сообщение с доступными позициями заказа.
```

Этот план закрывает тогдашний этап разработки **"Оформление заказа и WhatsApp"**.

## 3. Scope работ

### 3.1. Переход к оформлению заказа

Нужно:

- добавить из корзины понятный переход к оформлению заказа;
- использовать страницу `/checkout`;
- не давать перейти к отправке заказа, если корзина пустая или в ней нет доступных позиций;
- при открытии оформления показать выбранные позиции, сумму доступных позиций и итоговую строку доставки;
- сохранить возможность вернуться к каталогу, если клиенту нужно изменить состав заказа.

### 3.2. Актуализация корзины на оформлении

Нужно:

- переиспользовать серверный `POST /api/cart/resolve`;
- актуализировать корзину при открытии `/checkout`;
- повторно актуализировать корзину перед отправкой в WhatsApp;
- удалить из локальной корзины скрытые и удаленные позиции;
- оставить видимыми позиции, которые стали **нет в наличии**, но не учитывать их в сумме и не отправлять в WhatsApp;
- обновить цену, если она изменилась;
- показать официальные предупреждения для недоступных позиций и измененных цен.

### 3.3. Форма оформления

Нужно:

- добавить обязательное поле адреса доставки;
- показать в поле адреса пример `Грозный ул. Назабраева 92`;
- не спрашивать имя клиента;
- не спрашивать телефон клиента;
- добавить обязательный выбор способа оплаты:
  - `наличные`;
  - `перевод`;
- показать ошибку, если адрес не указан;
- показать ошибку, если способ оплаты не выбран;
- не проверять город в адресе.

### 3.4. Доставка на оформлении

Нужно:

- считать сумму только по доступным позициям;
- если сумма доступных позиций от `8000` рублей включительно, показывать текст `Доставка: бесплатно по г. Грозный`;
- если сумма доступных позиций меньше `8000` рублей, показывать текст `Доставка: стоимость сообщим в WhatsApp по тарифу`;
- не показывать точную итоговую сумму с доставкой, если сумма товаров меньше `8000` рублей;
- не рассчитывать доставку автоматически по адресу.

### 3.5. WhatsApp-сообщение

Нужно:

- формировать сообщение только из доступных позиций;
- начинать сообщение с фразы `Добрый день! Хочу сделать заказ!`;
- использовать компактные строки товаров:

```text
Название товара вкус - 1уп
Название товара - 1уп
```

- добавить в сообщение:
  - блок `Товары:`;
  - сумму товаров;
  - итоговую строку доставки;
  - адрес доставки;
  - способ оплаты;
- не добавлять эмодзи, чтобы на устройствах клиента и работника не появлялись вопросительные знаки;
- не добавлять источник заказа;
- не добавлять дату и время;
- не добавлять фразу `Пожалуйста, подтвердите заказ`;
- не расписывать в строках товара отдельные поля цены и суммы;
- URL-encode текст сообщения для ссылки WhatsApp.

### 3.6. Открытие WhatsApp

Нужно:

- открыть WhatsApp через ссылку `https://wa.me/{phone}?text={encodedMessage}`;
- использовать номер владельца для `wa.me` в формате `79380046199`;
- хранить номер WhatsApp в настройках окружения без отправки секретов в браузер;
- после перехода по WhatsApp-ссылке очистить корзину;
- показать официальное сообщение об ошибке, если WhatsApp не открылся;
- обработать слишком длинное сообщение официальным сообщением с предложением уменьшить заказ;
- не добавлять предпросмотр WhatsApp-сообщения;
- не добавлять кнопку копирования текста заказа.

## 4. Что не входит в этот план

В этот work plan не входит:

- полный редизайн клиентского каталога и корзины;
- админка входа;
- админка управления каталогом;
- сохранение заказа в базе данных;
- история заказов;
- CRM;
- онлайн-оплата;
- регистрация клиента;
- ввод имени клиента;
- ввод телефона клиента;
- автоматическая проверка города в адресе;
- автоматический расчет точной доставки;
- изменение схемы базы данных;
- деплой на Vercel.

## 5. Проверки

После реализации нужно проверить:

```text
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run build
git diff --check
git status --short --branch
```

Дополнительно вручную проверить локально:

- из корзины можно перейти на `/checkout`;
- пустую корзину нельзя отправить в WhatsApp;
- корзину без доступных позиций нельзя отправить в WhatsApp;
- доступные и недоступные позиции показываются понятно;
- в WhatsApp попадают только доступные позиции;
- сумма считается только по доступным позициям;
- при сумме меньше `8000` рублей показывается `Доставка: стоимость сообщим в WhatsApp по тарифу`;
- при сумме ровно `8000` рублей показывается `Доставка: бесплатно по г. Грозный`;
- при сумме больше `8000` рублей показывается `Доставка: бесплатно по г. Грозный`;
- без адреса заказ нельзя отправить;
- без способа оплаты заказ нельзя отправить;
- адрес попадает в WhatsApp-сообщение;
- способ оплаты попадает в WhatsApp-сообщение;
- WhatsApp-сообщение не содержит эмодзи;
- строка товара без вкуса формируется как `Название товара - 1уп`;
- строка товара с вкусом формируется как `Название товара вкус - 1уп`;
- сообщение начинается с `Добрый день! Хочу сделать заказ!`;
- источник заказа, дата, время и фраза подтверждения не добавляются;
- после перехода по WhatsApp-ссылке корзина очищается;
- клиент видит официальное сообщение, если WhatsApp не открылся;
- страница оформления удобно открывается на телефоне и компьютере.

## 6. Критерии готовности

План считается выполненным, когда:

- клиент может открыть оформление заказа после сбора корзины;
- адрес доставки обязателен;
- способ оплаты обязателен;
- итоговая строка доставки соответствует spec `04-delivery`;
- WhatsApp-сообщение соответствует feature и technical specs;
- недоступные позиции не попадают в WhatsApp;
- заказ не сохраняется в базе данных;
- корзина очищается после перехода по WhatsApp-ссылке;
- интерфейс и сообщения на русском языке;
- проверки завершились успешно;
- результат показан владельцу для ручной проверки.
