# Work Plan: Страница корзины и окно оформления заказа

Дата: 2026-06-14

Статус: active

Рабочая ветка после утверждения плана: `feature/cart-page-checkout-modal`

## 1. Цель

Переделать путь клиента после добавления товаров:

```text
Каталог -> страница корзины /cart -> окно оформления заказа поверх корзины -> WhatsApp
```

Главный результат:

```text
Корзина открывается как отдельная удобная страница с фото товаров, а оформление заказа открывается почти полноэкранным окном поверх этой страницы.
```

## 3. Scope работ

### 3.1. Страница корзины

Нужно:

- добавить публичную страницу `/cart`;
- перенести полный состав корзины из окна на страницу `/cart`;
- показать для каждой позиции фото, название, выбранный вкус, цену, количество, сумму позиции;
- для фото использовать фото выбранного вкуса, если оно есть, иначе основное фото товара;
- оставить изменение количества только через плюс и минус;
- оставить удаление отдельной позиции;
- оставить очистку всей корзины;
- показать общую сумму товаров только по доступным позициям;
- показать подсказку по бесплатной доставке по правилам `04-delivery`;
- добавить кнопку **Продолжить покупки** для возврата в каталог;
- добавить кнопку **Оформить заказ**;
- показать понятное пустое состояние, если корзина пустая.

### 3.2. Переход из каталога

Нужно:

- показывать компактную кнопку-иконку корзины в правом верхнем углу каталога всегда, даже если корзина пустая;
- сделать компактную кнопку-иконку корзины переходом на `/cart`;
- после добавления товара показывать дополнительную длинную кнопку перехода в корзину с текстом **Корзина** и счетчиком уп;
- не открывать корзину как модальное окно или нижнюю панель;
- не открывать корзину автоматически после добавления товара или изменения количества на карточке.

### 3.3. Окно оформления заказа

Нужно:

- перенести оформление заказа из отдельной страницы в компонент окна;
- открывать окно кнопкой **Оформить заказ** на странице `/cart`;
- на телефоне показывать оформление как почти полноэкранное окно поверх корзины;
- в окне оставить адрес доставки, выбор оплаты, итоговую строку доставки и кнопку **Отправить в WhatsApp**;
- если клиент закрывает окно оформления, оставлять его на странице `/cart`;
- не терять корзину при закрытии окна;
- перед отправкой в WhatsApp актуализировать корзину через `POST /api/cart/resolve`;
- после перехода по WhatsApp-ссылке очищать корзину.

### 3.4. Удаление старого маршрута

Нужно:

- удалить отдельную страницу `/checkout`;
- убрать переходы на `/checkout`;
- не делать редирект со старого `/checkout`;
- если открыть `/checkout` вручную, отдельной страницы оформления быть не должно.

### 3.5. Актуализация данных корзины

Нужно:

- расширить данные, которые используются для отображения корзины, актуальной ссылкой на фото;
- не считать `localStorage` источником истины для цены, доступности и фото;
- удалять из корзины скрытые и удаленные позиции после актуализации;
- оставлять недоступные позиции видимыми, но не учитывать их в сумме и WhatsApp-сообщении;
- показывать предупреждения для недоступных позиций и изменившихся цен.

## 4. Что не входит в этот план

В этот work plan не входит:

- полный редизайн всего клиентского каталога;
- изменение карточек товаров за пределами кнопки перехода в корзину;
- изменение WhatsApp-формата, кроме сохранения текущей логики в новом окне;
- сохранение заказов в базе данных;
- онлайн-оплата;
- админка;
- деплой на Vercel;
- изменение схемы базы данных.

## 5. Проверки

После реализации нужно выполнить:

```text
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run build
git diff --check
git status --short --branch
```

Дополнительно вручную проверить:

- товар добавляется из каталога;
- компактная иконка корзины видна в правом верхнем углу даже при пустой корзине и ведет на `/cart`;
- после добавления товара появляется длинная кнопка **Корзина** со счетчиком и ведет на `/cart`;
- на `/cart` видны фото товаров;
- фото вкуса показывается вместо основного фото товара, если у вкуса есть свое фото;
- если у вкуса нет фото, показывается основное фото товара;
- плюс и минус работают на карточке товара и на странице корзины;
- удаление позиции работает;
- очистка корзины работает;
- пустая корзина показывает понятное состояние;
- **Продолжить покупки** возвращает в каталог;
- **Оформить заказ** открывает почти полноэкранное окно поверх корзины;
- закрытие окна оформления возвращает к корзине без потери товаров;
- адрес доставки обязателен;
- способ оплаты обязателен;
- WhatsApp-сообщение формируется в текущем утвержденном формате;
- после перехода по WhatsApp-ссылке корзина очищается;
- `/checkout` больше не открывает отдельную страницу оформления.

## 6. Критерии готовности

План считается выполненным, когда:

- корзина работает как отдельная страница `/cart`;
- оформление заказа работает как почти полноэкранное окно поверх `/cart`;
- старый маршрут `/checkout` удален;
- путь клиента соответствует схеме `Каталог -> /cart -> окно оформления -> WhatsApp`;
- интерфейс и сообщения остаются на русском языке;
- проверки завершены успешно;
- результат показан владельцу для ручной проверки.

## 7. Git-порядок после утверждения

После утверждения владельцем:

1. Перейти на `main`.
2. Обновить `main` через `git pull --ff-only origin main`.
3. Создать ветку `feature/cart-page-checkout-modal`.
4. Выполнить только scope этого work plan.
5. Запустить проверки.
6. Показать результат владельцу для ручной проверки.
7. Commit и push делать только после отдельной просьбы владельца.
