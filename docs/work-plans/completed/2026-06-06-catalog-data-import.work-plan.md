# Work Plan: Загрузка данных старого каталога в Supabase

Дата: 2026-06-06

Статус: completed

Рабочая ветка после утверждения плана: `feature/catalog-data-import`

## 1. Цель

Загрузить текущий ассортимент старого каталога в Supabase Postgres и Supabase Storage через уже подготовленный импорт.

Главный результат этого плана:

```text
В тестовом Supabase есть реальные категории, товары, вкусы, фото и связи между ними.
```

Этот план закрывает этап roadmap **"Импорт реальных данных"**.

## 3. Входные данные

Используем:

- `data/import/old-catalog-products.draft.json`;
- `data/source-old-catalog/photos/`;
- `scripts/import-old-catalog.ts`;
- текущий тестовый Supabase из локального `.env`.

Ожидаемое состояние по dry-run предыдущего этапа:

- 7 категорий найдены в Supabase;
- 82 images к созданию;
- 86 товаров к созданию;
- 108 вкусов к созданию;
- 4 товара останутся черновиками;
- ошибок и предупреждений нет.

## 4. Scope работ

### 4.1. Предварительная проверка

Перед записью нужно:

- убедиться, что работа идет из актуального `main`;
- создать ветку `feature/catalog-data-import`;
- проверить, что локальный `.env` существует;
- не выводить значения секретов и ключей в лог;
- выполнить `npm.cmd run storage:ensure`;
- выполнить `npm.cmd run catalog:import:validate`;
- выполнить `npm.cmd run catalog:import:dry-run`;
- убедиться, что dry-run не показывает ошибок.

Если `.env` указывает на боевой Supabase или это невозможно безопасно понять, остановиться и уточнить у владельца.

### 4.2. Реальная запись в Supabase

Запись выполняется только в тестовый Supabase.

Команда записи:

```text
npm.cmd exec tsx scripts/import-old-catalog.ts -- --write --confirm-write=OLD_CATALOG_IMPORT
```

Ожидаемые действия:

- загрузить 82 фото в Storage bucket `product-images`;
- создать или обновить записи в таблице `images`;
- создать или обновить 86 товаров;
- создать или обновить 108 вкусов;
- связать товары и вкусы с фото;
- сохранить 4 товара без основного фото как `draft`;
- сохранить начальный порядок товаров для **Все напитки** и внутри категорий.

### 4.3. Проверка после записи

После записи нужно проверить:

- `npm.cmd run db:check`;
- `npm.cmd run catalog:import:dry-run`;
- что повторный dry-run показывает обновление уже существующих записей, а не повторное создание всего каталога;
- что в Supabase Postgres есть 86 товаров;
- что в Supabase Postgres есть 108 вкусов;
- что в Supabase Postgres есть 82 записи images для импортируемых фото;
- что Storage bucket `product-images` содержит загруженные файлы с путями `old-catalog/<имя-файла>`;
- что публичные ссылки на фото открываются;
- что 4 товара без основного фото имеют статус `draft`.

### 4.4. Отчет результата

Создать отчет:

```text
data/import/old-catalog-import-result-report.md
```

Отчет должен фиксировать:

- дату импорта;
- какие команды были выполнены;
- сколько товаров, вкусов и images записано;
- сколько товаров осталось черновиками;
- какие 4 товара остались черновиками;
- сколько фото загружено в Storage;
- результат повторного dry-run;
- подтверждение, что запись выполнялась только в тестовый Supabase;
- ошибки или предупреждения, если они были.

## 5. Что не входит в этот план

В этот work plan не входит:

- загрузка данных в боевой Supabase;
- деплой на Vercel;
- клиентский каталог на реальных данных;
- корзина;
- оформление заказа и WhatsApp;
- админка входа;
- админка управления каталогом;
- исправление отсутствующих фото у 4 черновиков;
- удаление неиспользуемых фото;
- изменение схемы базы данных.

## 7. Критерии готовности

План считается выполненным, когда:

- импорт записал данные в тестовый Supabase;
- в базе есть 86 товаров;
- в базе есть 108 вкусов;
- импортируемые фото загружены в Storage;
- публичные ссылки на фото работают;
- 4 товара без основного фото остались черновиками;
- повторный dry-run не создает дубли;
- результат зафиксирован в отчете;
- проверки завершились успешно.

3. Выполнить только scope этого плана.
4. Показать результат владельцу для проверки.
5. Commit и push делать только после отдельной просьбы владельца.
